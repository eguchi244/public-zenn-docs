# はじめに
この書籍は、ブラウザで動く **JavaScript のタスク管理アプリ** と、Python の **FastAPI で作ったタスク管理 API** をつなぎ、1つのアプリとして動かすことを目的としています。

画面（フロントエンド）と API（バックエンド）を別々に作れるようになると、次に必ずぶつかるのが「**この2つをどうつなぐのか**」です。

- 画面から API を呼び出すには、JavaScript で HTTP リクエストを送る（`fetch`）
- 通信には時間がかかるので、結果を待つ書き方（`async` / `await`）が要る
- 画面と API が別の場所（オリジン）から配信されていると、ブラウザが通信をブロックする（CORS）
- 通信は失敗することがあるので、ローディング表示やエラー表示が要る

この書籍では、これらを手を動かしながら1つずつ体験していきます。

:::message
この書籍は、次の2冊で作ったアプリを合流させる続編です。

- 『JavaScript入門 - タスク管理アプリを作ってみよう!』（画面）
- 『FastAPI入門 - タスク管理APIを作ってみよう!』（API）

前作を読んでいなくても進められるように、**出発点のコードは公開リポジトリから取得できる**ようにしています（入門03）。必要な前提知識は、この章の「前作のおさらい」で紹介します。
:::

# ①作るもの
前作のタスク管理アプリと見た目はほぼ同じですが、**タスクのデータを API サーバー（データベース）に保存する**アプリです。

画面で追加・完了切り替え・削除をすると、その操作が HTTP リクエストとして API に送られ、データベースに保存されます。ブラウザを変えても、リロードしても、同じ一覧が表示されます。

完成版の画面は次のとおりです。4件のタスクのうち、2件目を完了にしたところです。前作にあったフィルタータブ（すべて / 未完了 / 完了済み）はありません（理由は入門02で説明します）。

## 機能要件
### フロントエンド（画面）
| # | 要件 |
|---|------|
| F-01 | ページ読み込み時に API からタスク一覧を取得して表示する |
| F-02 | タスク追加フォームの送信時に POST リクエストで API にタスクを登録する |
| F-03 | チェックボックスの操作時に PUT リクエストで API の完了状態を更新する |
| F-04 | 削除ボタンの押下時に DELETE リクエストで API のタスクを削除する |
| F-05 | API リクエスト中はローディング表示（通信中...）を出す |
| F-06 | API エラー時はエラーメッセージを画面に表示する |

| # | 要件 |
|---|------|

# ②学習目標
この書籍を終えると、次のことができるようになります。

- `fetch` API を使って GET / POST / PUT / DELETE リクエストを送れる
- `async` / `await` による非同期処理を理解して書ける
- FastAPI の CORS 設定の意味を理解して、正しく設定できる

# ③前作のおさらい
この書籍は、前作2冊の完成版のコードから出発します。前作を読んでいない方は、ここで要点だけ押さえておきましょう。

## タスク管理アプリ（画面）
『JavaScript入門 - タスク管理アプリを作ってみよう!』で作った、フレームワークを使わない素の JavaScript のアプリです。

https://zenn.dev/eguchi244_dev/books/js-task-tutorial-eguchi244

この書籍で引き継ぐのは、次の骨格です。

- **状態 → 描画:** タスクの一覧を配列（`tasks`）で持ち、`render()` が配列から画面を全部描き直す
- **イベントデリゲーション:** 一覧の親要素 `<ul>` で、チェックボックスと削除ボタンのクリックをまとめて受け取る。どのタスクの何の操作かは `data-id` / `data-action` 属性で見分ける
- **XSS 対策:** タスク名は `textContent` で表示し、HTML として解釈させない
- **保存先は `localStorage`:** 配列を `JSON.stringify` で文字列にしてブラウザに保存する。そのため、データはそのブラウザの中にしか無い

## タスク管理 API
『FastAPI入門 - タスク管理APIを作ってみよう!』で作った、タスクの作成・取得・更新・削除ができる API です。

https://zenn.dev/eguchi244_dev/books/fastapi-task-tutorial-eguchi244

この書籍で使うエンドポイントは次の4本です。

| 操作 | メソッドとパス | 成功時のレスポンス |
|------|----------------|--------------------|
| 一覧取得 | `GET /tasks` | 200・タスクの配列 |
| 作成 | `POST /tasks` | 201・作成したタスク |
| 更新（部分更新） | `PUT /tasks/{id}` | 200・更新したタスク |
| 削除 | `DELETE /tasks/{id}` | 200・`{"ok": true}` |

- データは SQLite（`tasks.db`）に保存され、サーバーを再起動しても残る
- `http://localhost:8000/docs` を開くと、Swagger UI（API の説明書兼お試し画面）から API を直接呼び出せる
- 更新は、送った項目だけを書き換える**部分更新**。`{"completed": true}` だけを送れば、完了状態だけが変わる

この2つを「画面はそのまま、データの置き場所だけを `localStorage` から API に移す」形でつなぐのが、この書籍の内容です。

## Python・VS Code・Live Server を用意する
Windows の場合は、PowerShell で次のコマンドを実行するとインストールできます。

```powershell:PowerShell
winget install Python.Python.3.12
winget install Microsoft.VisualStudioCode
code --install-extension ritwickdey.LiveServer
```

インストールしたらターミナルを開き直し、バージョンが表示されることを確認します。

```powershell:PowerShell
python --version
```

:::message
`code` コマンドが見つからない場合は、VS Code をインストールしたあとにターミナルを開き直してください。Python の環境構築の詳しい手順は、下記の記事でも紹介しています。
https://zenn.dev/eguchi244_dev/articles/python-vscode-windows-setup-20261015
