# 追加・完了切り替え・削除をAPIにつなぐ
第5章では、タスクの追加・完了切り替え・削除を、API への POST / PUT / DELETE のリクエストに書き換えます（Phase 3）。

前作で `localStorage` に書いていた3つの操作を、それぞれ HTTP メソッドに対応させます。

| 操作 | 前作（localStorage） | この書籍（API） |
|------|------------------|-----------|
| 追加 | `tasks.push` + `saveTasks()` | `POST /tasks` |
| 完了切り替え | `task.completed = !task.completed` + `saveTasks()` | `PUT /tasks/{id}` |
| 削除 | `tasks.filter` + `saveTasks()` | `DELETE /tasks/{id}` |

# 今回の目標物
- 画面からタスクを追加・完了切り替え・削除できる
- リロードしても、別のブラウザで開いても、同じ一覧が表示される
- Network タブで、POST / PUT / DELETE のリクエストが確認できる

完成すると次の画面になります。画面の入力欄からタスクを3件追加し、2件目のチェックボックスをクリックしたところです。見た目は前作と同じですが、この一覧は POST・PUT のあとにサーバーから取り直したものです。リロードしても同じ表示に戻ります。

# ①書き込み系の API 関数を追加する
`frontend/script.js` の `fetchTasks` の下に、3つの関数を追加します。

あわせて、API 通信のセクションの見出しに「書いたら取り直す」方針を NOTE として書き添えておきます。

```js:frontend/script.js
// ==========================================
// API通信
//
// NOTE: 書き込み系（追加・完了切替・削除）は最後に必ずfetchTasksで取り直します
// フロント側の配列も更新して画面を合わせると、真実のソースがサーバーとフロントの2つになるためです
// ==========================================
```

## 追加 ― addTask
```js:frontend/script.js
/**
 * タスクを新規作成して一覧を取り直す
 *
 * @param {string} title - タスクのタイトル
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function addTask(title) {
  // FastAPIからタスク新規作成を取得
  const res = await fetch(`${API_BASE}/tasks`, {
    method  : 'POST',
    headers : { 'Content-Type': 'application/json' },
    body    : JSON.stringify({ title }),
  });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`POST /tasks failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}
```

### POST と PUT には「何を送るか」が要る
`fetch` の第2引数に、リクエストの中身を指定します。

| 項目 | 内容 |
|------|------|
| `method` | HTTP メソッド。省略すると `GET` |
| `headers` | `Content-Type: application/json` で「本文は JSON です」と宣言する |
| `body` | 送る本文。オブジェクトのままでは送れないので、`JSON.stringify` で文字列にする |

`Content-Type` を付け忘れると、FastAPI は本文を JSON として読めず、422 エラーを返します。

前作で `localStorage` に保存するときに使った `JSON.stringify` が、今度は**ネットワークに送る**ために登場します。どちらも「オブジェクトを文字列にして、外へ持ち出す」という同じ役割です。

## 完了切り替え ― toggleTask
```js:frontend/script.js
/**
 * タスクの完了状態を更新して一覧を取り直す
 *
 * NOTE: 送るのは completed だけの部分更新です（APIのTaskUpdateは全項目が任意のため）
 *
 * @param {string} id - タスクのID（data-id属性から取得するため文字列）
 * @param {boolean} completed - 更新後の完了状態
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function toggleTask(id, completed) {
  // FastAPIから指定タスクの更新を取得
  const res = await fetch(`${API_BASE}/tasks/${id}`, {
    method  : 'PUT',
    headers : { 'Content-Type': 'application/json' },
    body    : JSON.stringify({ completed }),
  });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`PUT /tasks/${id} failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}
```

送るのは `{"completed": true}` のように、**完了状態だけ**です。API の更新用のモデル（`TaskUpdate`）は全項目が省略可能になっていて、送らなかった項目（`title`）は変更されません。前作の API で部分更新を作っておいたのは、こういう使い方をするためです。

:::message
`id` は数値ですが、引数の型は文字列にしています。HTML の `data-id` 属性から取り出した値は、必ず文字列になるためです。URL に埋め込むだけなので、文字列のままで問題ありません。
:::

## 削除 ― deleteTask
```js:frontend/script.js
/**
 * 指定IDのタスクを削除して一覧を取り直す
 *
 * @param {string} id - タスクのID（data-id属性から取得するため文字列）
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function deleteTask(id) {
  // FastAPIから指定タスクの削除を取得
  const res = await fetch(`${API_BASE}/tasks/${id}`, { method: 'DELETE' });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`DELETE /tasks/${id} failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}
```

DELETE は送る本文が無いので、`method` だけを指定します。

# ②「書いたら、取り直す」― サーバーを正とした同期
3つの関数は、どれも最後が `await fetchTasks()` です。

「フロント側でも配列を書き換えて、画面だけ先に合わせる」こともできます。しかし、それは**正しいデータの置き場所が2つ**（サーバーとフロント）になる道です。たとえば、追加には成功したのにフロントの配列の更新を間違えると、画面とデータベースが食い違ってしまいます。

多少通信が増えても、書き込みに成功したあとにサーバーから取り直せば、画面は常にデータベースと一致します。

:::message
この「取り直し」の通信を減らす工夫（キャッシュなど）を自動でしてくれるのが、React Query（TanStack Query）などのライブラリの役割です。まずは原型として、「書いたら取り直す」を体で覚えておきましょう。
:::

# ③イベントとつなぐ
前作とほぼ同じイベントの構成ですが、呼び出す関数が非同期になります。初期表示の `fetchTasks();` の**前**に追加してください。

## フォームの送信 ― handleTaskSubmit
```js:frontend/script.js
// ==========================================
// イベントハンドラー
// ==========================================

/**
 * タスク入力欄の送信イベントを処理する
 *
 * @param {SubmitEvent} event - フォーム送信のイベントオブジェクト
 */
function handleTaskSubmit(event) {
  // Formの規定動作を止める（SPA用のページリロード対策）
  event.preventDefault();

  // バリデーション
  // NOTE: 前後の空白を除去した結果が空文字なら追加しない
  const title = taskInput.value.trim();
  if (title === '') return;

  // タスクリストを作成・保存して描画する
  addTask(title).then(() => {
    // タスク入力欄を空にしてフォーカスする
    taskInput.value = '';
    taskInput.focus();
  });
}
```

`addTask(title)` は Promise を返します。`.then()` は、非同期の処理が**終わったあと**に実行したい処理をつなぐための仕組みです。ここでは、API への登録が終わったあとに入力欄を空にしています。

この書き方は入門06で `await` を使った形に書き換えます（理由もそこで説明します）。

## 一覧のクリック ― handleTaskListClick
```js:frontend/script.js
/**
 * タスクリスト内のクリックイベントを処理する（イベント移譲）
 *
 * NOTE: タスクリストの削除・完了切り替えを action に応じて実行する
 * @param {MouseEvent} event - クリックイベントのオブジェクト
 */
function handleTaskListClick(event) {
  // クリックされた要素の data-id と data-action を取得
  const { id, action } = event.target.dataset;

  // idが存在しない場合は何もしない
  if (!id) return;

  // actionに応じた状態更新を実行する
  if (action === 'delete') {
    deleteTask(id);
  } else if (action === 'toggle') {
    toggleTask(id, event.target.checked);
  } else {
    return;
  }
}
```

### チェックボックスの値をそのまま送る
前作では `task.completed = !task.completed` と、フロントで完了状態を反転していました。

この書籍では、`event.target.checked`（**クリックしたあとの**チェックボックスの状態）を、そのまま PUT に渡します。チェックボックス自体が「新しい値」を知っているので、フロントに状態を持たなくても済みます。

## イベントリスナー
```js:frontend/script.js
// ==========================================
// イベントリスナー
// ==========================================

// --- タスク入力欄 ---
taskForm.addEventListener('submit', handleTaskSubmit);

// --- タスクリストの削除・完了切り替え（イベント移譲）---
taskList.addEventListener('click', handleTaskListClick);
```

フィルタータブのリスナーは無くなり、2つだけになりました。

# ④Network タブで通信を確かめる
画面の操作が、本当に HTTP リクエストになっているかを確かめます。

1. 画面で F12 → Network タブを開く（開いている間だけ記録されるので、操作の前に開く）
2. フィルターを「Fetch/XHR」にする（CSS や画像を除いて見やすくする）
3. 「Preserve log」にチェックを入れる（ページを移動・リロードしても記録を消さない）
4. 入力欄にタスク名を入れて「追加」をクリックする

`tasks` への **POST** と、それに続く **GET** の2行が記録されます。「書いたら取り直す」が、そのまま通信の記録に表れています。POST の行をクリックし、「Payload」タブを開くと、送った JSON（`{"title": "..."}`）を確認できます。

# ⑤動作確認
次の動作ができれば、この章は完了です。

- [✔] 画面からタスクを追加すると一覧に反映され、Network タブに POST が記録される
- [✔] チェックボックスで PUT、削除ボタンで DELETE が送られる（Network タブで確認）
- [✔] **リロードしても消えない**（保存先はもう `localStorage` ではなく、サーバーのデータベース）
- [✔] 画面を別のブラウザで開いても同じ一覧が見える（データがサーバーにある証拠）
- [✔] Swagger UI の `GET /tasks` でも、画面で加えた変更が確認できる

:::details frontend/script.js の全体コード
```js:frontend/script.js
/* ==========================================
 * タスク管理アプリ（API連携版）
 * fetchによるAPI通信・DOM描画・通信UI（ローディング/エラー表示）
 * ========================================*/

// ==========================================
// 型定義
// ==========================================

/**
 * APIが返すタスク1件
 *
 * @typedef {Object} Task
 * @property {number} id - タスクのID（DBが採番する）
 * @property {string} title - タスクの内容
 * @property {boolean} completed - 完了していれば true
 * @property {string} created_at - 作成日時（APIが返す日時の文字列）
 */

// ==========================================
// APIのベースURL
// ==========================================

/** APIサーバーのURL */
const API_BASE = 'http://localhost:8000';

// ==========================================
// DOM要素
// ==========================================

/** 通信中の表示 */
const loading   = document.getElementById('loading');
/** エラーメッセージの表示欄 */
const errorBox  = document.getElementById('error');
/** タスクの入力フォーム */
const taskForm  = document.getElementById('taskForm');
/** タスクの入力欄 */
const taskInput = document.getElementById('taskInput');
/** タスクの一覧を表示する要素 */
const taskList  = document.getElementById('taskList');
/** 残り件数と総件数を表示する要素 */
const taskCount = document.getElementById('taskCount');

// ==========================================
// API通信
//
// NOTE: 書き込み系（追加・完了切替・削除）は最後に必ずfetchTasksで取り直します
// フロント側の配列も更新して画面を合わせると、真実のソースがサーバーとフロントの2つになるためです
// ==========================================

/**
 * APIからタスク一覧を取得して画面に描画する
 *
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function fetchTasks() {
  // FastAPIからタスク一覧を取得
  const res = await fetch(`${API_BASE}/tasks`);

  // レスポンス結果を判定
  // NOTE: fetchは404や500でも例外にならずres.okがfalseになるだけなので、自分で例外に変換する必要がある
  if (!res.ok) throw new Error(`GET /tasks failed: ${res.status}`);

  // JSONをTasks配列に変換
  /** @type {Task[]} */
  const tasks = await res.json();

  // 画面を再描画
  render(tasks);
}

/**
 * タスクを新規作成して一覧を取り直す
 *
 * @param {string} title - タスクのタイトル
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function addTask(title) {
  // FastAPIからタスク新規作成を取得
  const res = await fetch(`${API_BASE}/tasks`, {
    method  : 'POST',
    headers : { 'Content-Type': 'application/json' },
    body    : JSON.stringify({ title }),
  });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`POST /tasks failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}

/**
 * タスクの完了状態を更新して一覧を取り直す
 *
 * NOTE: 送るのは completed だけの部分更新です（APIのTaskUpdateは全項目が任意のため）
 *
 * @param {string} id - タスクのID（data-id属性から取得するため文字列）
 * @param {boolean} completed - 更新後の完了状態
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function toggleTask(id, completed) {

  const res = await fetch(`${API_BASE}/tasks/${id}`, {
    method  : 'PUT',
    headers : { 'Content-Type': 'application/json' },
    body    : JSON.stringify({ completed }),
  });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`PUT /tasks/${id} failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}

/**
 * 指定IDのタスクを削除して一覧を取り直す
 *
 * @param {string} id - タスクのID（data-id属性から取得するため文字列）
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function deleteTask(id) {
  // FastAPIから指定タスクの削除を取得
  const res = await fetch(`${API_BASE}/tasks/${id}`, { method: 'DELETE' });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`DELETE /tasks/${id} failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}

// ==========================================
// DOM 描画
// ==========================================

/**
 * タスクリストのli要素を作成する
 *
 * @param {Task} task - タスク
 * @returns {HTMLLIElement}　li要素のタスクリスト
 */
function createTaskElement(task) {
  // li要素を作成する
  const li = document.createElement('li');
  li.className = task.completed ? 'task-item completed' : 'task-item';

  // checkbox要素を作成する
  const checkbox = document.createElement('input');
  checkbox.type = 'checkbox';
  checkbox.checked = task.completed;
  checkbox.dataset.id = task.id;
  checkbox.dataset.action = 'toggle';

  // タイトルのspan要素を作成する
  const title = document.createElement('span');
  title.className = 'task-title';
  title.textContent = task.title; // XSS対策(textContent使用)

  // 削除用のbtn要素を作成する
  const deleteBtn = document.createElement('button');
  deleteBtn.type = 'button';
  deleteBtn.className = 'btn btn-delete';
  deleteBtn.textContent = '削除';
  deleteBtn.dataset.id = task.id;
  deleteBtn.dataset.action = 'delete';

  // li要素に各要素をまとめて追加する
  li.append(checkbox, title, deleteBtn);
  return li;
}

/**
 * APIから取得したタスク一覧で画面を再描画する
 *
 * NOTE: フロントは状態を持たないため、描画対象は状態変数ではなく引数で受け取る
 *
 * @param {Task[]} tasks - APIから取得したタスク一覧
 */
function render(tasks) {
  // タスクリストの再描画（空にしてから生成し直す）
  taskList.innerHTML = '';
  tasks.forEach((task) => {
    taskList.appendChild(createTaskElement(task));
  });

  // フッター（残り件数 / 総件数）
  const remaining = tasks.filter((task) => !task.completed).length;
  taskCount.textContent = `残り ${remaining} 件 / 全 ${tasks.length} 件`;
}

// ==========================================
// イベントハンドラー
// ==========================================

/**
 * タスク入力欄の送信イベントを処理する

  // タスクリストを作成・保存して描画する
  addTask(title).then(() => {
    // タスク入力欄を空にしてフォーカスする
    taskInput.value = '';
    taskInput.focus();
  });
}

/**
 * タスクリスト内のクリックイベントを処理する（イベント移譲）
 *
 * NOTE: タスクリストの削除・完了切り替えを action に応じて実行する
 * @param {MouseEvent} event - クリックイベントのオブジェクト

  // idが存在しない場合は何もしない

    deleteTask(id);
  } else if (action === 'toggle') {
    toggleTask(id, event.target.checked);
  } else {
    return;
  }
}

// ==========================================
// イベントリスナー
// ==========================================

// --- タスク入力欄 ---

// --- タスクリストの削除・完了切り替え（イベント移譲）---

// ==========================================
// 初期表示（ページ読み込み時にAPIから一覧取得）
```

# まとめ
ここまでの内容で、画面のすべての操作が API とつながりました。

- POST / PUT には `method`・`Content-Type`・`JSON.stringify` した `body` を渡す
- 完了切り替えは、`completed` だけを送る部分更新
- 書き込んだら必ず `fetchTasks()` で取り直し、サーバーを唯一の正とする
- チェックボックスの値をそのまま送れば、フロントに状態を持たなくて済む

アプリとしてはもう動きますが、まだ「通信は必ず成功する」前提のままです。次の入門06では、通信中の表示と、通信に失敗したときの表示を追加して仕上げます。
