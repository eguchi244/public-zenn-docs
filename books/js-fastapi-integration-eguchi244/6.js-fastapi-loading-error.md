# ローディングとエラーの表示
第6章では、通信中の表示（ローディング）と、通信に失敗したときの表示（エラー）を追加して、アプリを完成させます（Phase 4）。

前作の `localStorage` は、まず失敗しません。しかし、**ネットワークは失敗します**。サーバーが止まっている・応答が遅い、といった状況を画面で扱えて、はじめて「通信するアプリ」の完成です。

# 今回の目標物
- 通信中は「通信中...」が表示される
- API が止まっているときに操作すると、「サーバーとの通信に失敗しました」が画面に表示される
- 追加に失敗しても、入力欄の文字が消えずに残る

完成すると次の画面になります。通信がうまくいっている間の見た目は入門05と同じで、通信中と失敗したときだけ、入力欄の上に表示が出ます（③動作確認で紹介します）。

![](/images/js-fastapi-integration-eguchi244/6.js-fastapi-loading-error/2026-10-27-20-11-47.png =650x)

# ①表示を切り替える関数を書く
`frontend/script.js` の「DOM 描画」のセクションの**前**に、次のセクションを追加します。

## showLoading・showError・clearError
```js:frontend/script.js
// ==========================================
// ローディング・エラー表示
// ==========================================

/**
 * ローディング表示（通信中...）の表示・非表示を切り替える
 *
 * @param {boolean} isLoading - 通信中ならtrue、通信が終わっていればfalse
 */
function showLoading(isLoading) {
  loading.classList.toggle('hidden', !isLoading);
}
```

`classList.toggle` の第2引数に `true` を渡すとクラスを付け、`false` を渡すと外します。通信中（`isLoading` が `true`）のときは `hidden` を外して表示し、そうでなければ `hidden` を付けて隠します。

```js:frontend/script.js
/**
 * エラーメッセージを画面に表示する
 *
 * @param {string} message - 画面に表示する文言
 */
function showError(message) {
  errorBox.textContent = message;
  errorBox.classList.remove('hidden');
}
```

```js:frontend/script.js
/**
 * エラー表示を消す
 */
function clearError() {
  errorBox.classList.add('hidden');
}
```

## apiCall ― 通信の前後の処理をまとめる
```js:frontend/script.js
/**
 * API呼び出しを包んで、ローディング表示とエラー処理を一元化する
 *
 * @param {() => Promise<void>} fn - 包んで実行するAPI呼び出し
 */
async function apiCall(fn) {
  try {
    clearError();
    showLoading(true);
    await fn();
  } catch (error) {
    // 通信に失敗した場合はUIにも表示する（コンソールだけではユーザーが気づけない）
    console.error(`予期しないエラー: ${error.name} ${error.message}`);
    showError('サーバーとの通信に失敗しました');
  } finally {
    // NOTE: 成功・例外のどちらの経路でも必ずローディング表示を消す
    showLoading(false);
  }
}
```

### 横断的な処理を1か所にまとめる
「始まったらローディングを出す」「失敗したらエラーを出す」「終わったら必ずローディングを消す」は、**どの API の操作でも同じ**です。

これを操作ごとに `try` / `catch` で書くと、同じコードがあちこちに増えます。そこで、「API を呼ぶ処理（関数）を受け取って、前後の処理で包んで実行する」関数 `apiCall` に集めます。このように、**関数を引数として受け取る関数**を高階関数と呼びます。

| 部分 | 役割 |
|------|------|
| `try` | 前回のエラー表示を消し、ローディングを出してから、受け取った `fn` の完了を待つ |
| `catch` | `fn` の中で投げられた例外（入門04の `res.ok` のチェックや、通信の失敗）を受け止め、画面にエラーを出す |
| `finally` | 成功・失敗のどちらでも、最後に必ずローディングを消す |

### finally ― 成功でも失敗でも必ず実行する
ローディングの消し忘れは、「通信中...が出っぱなしになる」という典型的なバグです。`finally` に置けば、成功・例外のどちらの経路でも必ず消えます。

### エラーは画面にも出す
`console.error` だけでは、開発者ツールを開いていない利用者は失敗に気づけません。何も起きないように見えて、もう一度ボタンを押す……ということになります。だから、画面にもエラーを出します。

# ②すべての呼び出しを apiCall で包む
イベントハンドラーと初期表示を、最終形に書き換えます。

## フォームの送信
```js:frontend/script.js
// ==========================================
// イベントハンドラー
// ==========================================

/**
 * タスク入力欄の送信イベントを処理する
 *
 * @param {SubmitEvent} event - フォーム送信のイベントオブジェクト
 */
function handleTaskSubmit(event) {
  // Formの規定動作を止める（SPA用のページリロード対策）
  event.preventDefault();

  // バリデーション
  // NOTE: 前後の空白を除去した結果が空文字なら追加しない
  const title = taskInput.value.trim();
  if (title === '') return;

  // タスクリストを作成・保存して描画する
  apiCall(async () => {
    await addTask(title);

    // タスク入力欄を空にしてフォーカスする
    // NOTE: クリアは追加が成功した後に行う（失敗時にはクリア処理はされない）
    taskInput.value = '';
    taskInput.focus();
  });
}
```

### 入力欄を空にするのは、追加に成功したあと
入力欄を空にする処理を、`await addTask(title)` の**あと**に置いている点に注目してください。

`addTask` が失敗すると、例外が投げられてその先の行は実行されず、`apiCall` の `catch` に飛びます。つまり、**失敗したときは入力欄が空にならず、文字が残ります**。失敗したときに入力が消えてしまうと、利用者はもう一度打ち直すことになるためです。

### .then() ではなく await を使う
入門05では `addTask(title).then(...)` と書いていました。これをそのまま `apiCall` で包むと、次のようになります。

```js
// うまくいかない例
apiCall(() => {
  addTask(title).then(() => { /* 入力欄を空にする */ });
});
```

この関数は、`addTask` の通信の**完了を待たずに**すぐ終わります（Promise を返していないため）。すると `apiCall` の `await fn()` もすぐに終わり、通信中なのに `finally` でローディングが消えてしまいます。さらに、`addTask` の失敗も `apiCall` の `catch` に届きません。

`async` の関数の中で `await addTask(title)` と書けば、`apiCall` は通信の完了まで待ち、失敗も受け止められます。

## 一覧のクリック
```js:frontend/script.js
/**
 * タスクリスト内のクリックイベントを処理する（イベント移譲）
 *
 * NOTE: タスクリストの削除・完了切り替えを action に応じて実行する
 * @param {MouseEvent} event - クリックイベントのオブジェクト
 */
function handleTaskListClick(event) {
  // クリックされた要素の data-id と data-action を取得
  const { id, action } = event.target.dataset;

  // idが存在しない場合は何もしない
  if (!id) return;

  // actionに応じたAPI呼び出しを実行する
  if (action === 'delete') {
    apiCall(() => deleteTask(id));
  } else if (action === 'toggle') {
    apiCall(() => toggleTask(id, event.target.checked));
  }
}
```

`() => deleteTask(id)` は、`deleteTask(id)` の Promise を**そのまま返す**アロー関数です。`apiCall` はこの Promise を `await` するので、通信の完了まで待てます。

## イベントリスナーと初期表示
```js:frontend/script.js
// ==========================================
// イベントリスナー
// ==========================================

// --- タスク入力欄 ---
taskForm.addEventListener('submit', handleTaskSubmit);

// --- タスクリストの削除・完了切り替え（イベント移譲）---
taskList.addEventListener('click', handleTaskListClick);
```

```js:frontend/script.js
// ==========================================
// 初期表示（ページ読み込み時にAPIから一覧取得）
// ==========================================

apiCall(fetchTasks);
```

ページ読み込み時の一覧取得も `apiCall` を通します。API が止まっているときにページを開くと、最初からエラーが表示されます。

# ③動作確認
通信中は、入力欄の上に「通信中...」が出ます。次の画像は「歯医者を予約する」を追加して、サーバーの応答を待っている瞬間です。まだ応答が届いていないので、一覧は2件のままです。

![](/images/js-fastapi-integration-eguchi244/6.js-fastapi-loading-error/2026-10-27-20-11-48.png =650x)

API を停止してから追加すると、「サーバーとの通信に失敗しました」が表示されます。入力欄の「部屋の掃除をする」は消えずに残っているので、API を起動し直せば、そのままもう一度「追加」を押せます。

![](/images/js-fastapi-integration-eguchi244/6.js-fastapi-loading-error/2026-10-27-20-11-49.png =650x)

次の動作ができれば、アプリの完成です。

- [✔] 操作の瞬間に「通信中...」が一瞬表示される
- [✔] **API を停止**（uvicorn のターミナルで `Ctrl + C`）してから追加・削除・リロードを試すと、「サーバーとの通信に失敗しました」が画面に表示される（コンソールだけでなく画面に出ることが大切）
- [✔] API を再起動して操作すると、エラー表示が消えて元に戻る
- [✔] 失敗した追加操作では、入力欄の文字が消えずに残っている

:::message
通信が速すぎて「通信中...」が見えない場合は、開発者ツールの Network タブで「No throttling」を「Slow 4G」に変えると、通信が遅くなって観察できます。確認が終わったら「No throttling」に戻してください。
:::

:::details frontend/script.js の全体コード
```js:frontend/script.js
/* ==========================================
 * タスク管理アプリ（API連携版）
 * fetchによるAPI通信・DOM描画・通信UI（ローディング/エラー表示）
 * ========================================*/

// ==========================================
// 型定義
// ==========================================

/**
 * APIが返すタスク1件
 *
 * @typedef {Object} Task
 * @property {number} id - タスクのID（DBが採番する）
 * @property {string} title - タスクの内容
 * @property {boolean} completed - 完了していれば true
 * @property {string} created_at - 作成日時（APIが返す日時の文字列）
 */

// ==========================================
// APIのベースURL
// ==========================================

/** APIサーバーのURL */
const API_BASE = 'http://localhost:8000';

// ==========================================
// DOM要素
// ==========================================

/** 通信中の表示 */
const loading   = document.getElementById('loading');
/** エラーメッセージの表示欄 */
const errorBox  = document.getElementById('error');
/** タスクの入力フォーム */
const taskForm  = document.getElementById('taskForm');
/** タスクの入力欄 */
const taskInput = document.getElementById('taskInput');
/** タスクの一覧を表示する要素 */
const taskList  = document.getElementById('taskList');
/** 残り件数と総件数を表示する要素 */
const taskCount = document.getElementById('taskCount');

// ==========================================
// API通信
//
// NOTE: 書き込み系（追加・完了切替・削除）は最後に必ずfetchTasksで取り直します
// フロント側の配列も更新して画面を合わせると、真実のソースがサーバーとフロントの2つになるためです
// ==========================================

/**
 * APIからタスク一覧を取得して画面に描画する
 *
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function fetchTasks() {
  // FastAPIからタスク一覧を取得
  const res = await fetch(`${API_BASE}/tasks`);

  // レスポンス結果を判定
  // NOTE: fetchは404や500でも例外にならずres.okがfalseになるだけなので、自分で例外に変換する必要がある
  if (!res.ok) throw new Error(`GET /tasks failed: ${res.status}`);

  // JSONをTasks配列に変換
  /** @type {Task[]} */
  const tasks = await res.json();

  // 画面を再描画
  render(tasks);
}

/**
 * タスクを新規作成して一覧を取り直す
 *
 * @param {string} title - タスクのタイトル
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function addTask(title) {
  // FastAPIからタスク新規作成を取得
  const res = await fetch(`${API_BASE}/tasks`, {
    method  : 'POST',
    headers : { 'Content-Type': 'application/json' },
    body    : JSON.stringify({ title }),
  });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`POST /tasks failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}

/**
 * タスクの完了状態を更新して一覧を取り直す
 *
 * NOTE: 送るのは completed だけの部分更新です（APIのTaskUpdateは全項目が任意のため）
 *
 * @param {string} id - タスクのID（data-id属性から取得するため文字列）
 * @param {boolean} completed - 更新後の完了状態
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function toggleTask(id, completed) {
  // FastAPIから指定タスクの更新を取得
  const res = await fetch(`${API_BASE}/tasks/${id}`, {
    method  : 'PUT',
    headers : { 'Content-Type': 'application/json' },
    body    : JSON.stringify({ completed }),
  });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`PUT /tasks/${id} failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}

/**
 * 指定IDのタスクを削除して一覧を取り直す
 *
 * @param {string} id - タスクのID（data-id属性から取得するため文字列）
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function deleteTask(id) {
  // FastAPIから指定タスクの削除を取得
  const res = await fetch(`${API_BASE}/tasks/${id}`, { method: 'DELETE' });

  // レスポンス結果を判定
  if (!res.ok) throw new Error(`DELETE /tasks/${id} failed: ${res.status}`);

  // タスク一覧を再取得して再描画
  await fetchTasks();
}

// ==========================================
// ローディング・エラー表示
// ==========================================

/**
 * ローディング表示（通信中...）の表示・非表示を切り替える
 *
 * @param {boolean} isLoading - 通信中ならtrue、通信が終わっていればfalse
 */
function showLoading(isLoading) {
  loading.classList.toggle('hidden', !isLoading);
}

/**
 * エラーメッセージを画面に表示する
 *
 * @param {string} message - 画面に表示する文言
 */
function showError(message) {
  errorBox.textContent = message;
  errorBox.classList.remove('hidden');
}

/**
 * エラー表示を消す
 */
function clearError() {
  errorBox.classList.add('hidden');
}

/**
 * API呼び出しを包んで、ローディング表示とエラー処理を一元化する
 *
 * @param {() => Promise<void>} fn - 包んで実行するAPI呼び出し
 */
async function apiCall(fn) {
  try {
    clearError();
    showLoading(true);
    await fn();
  } catch (error) {
    // 通信に失敗した場合はUIにも表示する（コンソールだけではユーザーが気づけない）
    console.error(`予期しないエラー: ${error.name} ${error.message}`);
    showError('サーバーとの通信に失敗しました');
  } finally {
    // NOTE: 成功・例外のどちらの経路でも必ずローディング表示を消す
    showLoading(false);
  }
}

// ==========================================
// DOM 描画
// ==========================================

/**
 * タスクリストのli要素を作成する
 *
 * @param {Task} task - タスク
 * @returns {HTMLLIElement}　li要素のタスクリスト
 */
function createTaskElement(task) {
  // li要素を作成する
  const li = document.createElement('li');
  li.className = task.completed ? 'task-item completed' : 'task-item';

  // checkbox要素を作成する
  const checkbox = document.createElement('input');
  checkbox.type = 'checkbox';
  checkbox.checked = task.completed;
  checkbox.dataset.id = task.id;
  checkbox.dataset.action = 'toggle';

  // タイトルのspan要素を作成する
  const title = document.createElement('span');
  title.className = 'task-title';
  title.textContent = task.title; // XSS対策(textContent使用)

  // 削除用のbtn要素を作成する
  const deleteBtn = document.createElement('button');
  deleteBtn.type = 'button';
  deleteBtn.className = 'btn btn-delete';
  deleteBtn.textContent = '削除';
  deleteBtn.dataset.id = task.id;
  deleteBtn.dataset.action = 'delete';

  // li要素に各要素をまとめて追加する
  li.append(checkbox, title, deleteBtn);
  return li;
}

/**
 * APIから取得したタスク一覧で画面を再描画する
 *
 * NOTE: フロントは状態を持たないため、描画対象は状態変数ではなく引数で受け取る
 *
 * @param {Task[]} tasks - APIから取得したタスク一覧
 */
function render(tasks) {
  // タスクリストの再描画（空にしてから生成し直す）
  taskList.innerHTML = '';
  tasks.forEach((task) => {
    taskList.appendChild(createTaskElement(task));
  });

  // フッター（残り件数 / 総件数）
  const remaining = tasks.filter((task) => !task.completed).length;
  taskCount.textContent = `残り ${remaining} 件 / 全 ${tasks.length} 件`;
}

// ==========================================
// イベントハンドラー
// ==========================================

/**
 * タスク入力欄の送信イベントを処理する
 *
 * @param {SubmitEvent} event - フォーム送信のイベントオブジェクト
 */
function handleTaskSubmit(event) {
  // Formの規定動作を止める（SPA用のページリロード対策）
  event.preventDefault();

  // バリデーション
  // NOTE: 前後の空白を除去した結果が空文字なら追加しない
  const title = taskInput.value.trim();
  if (title === '') return;

  // タスクリストを作成・保存して描画する
  apiCall(async () => {
    await addTask(title);

    // タスク入力欄を空にしてフォーカスする
    // NOTE: クリアは追加が成功した後に行う（失敗時にはクリア処理はされない）
    taskInput.value = '';
    taskInput.focus();
  });
}

/**
 * タスクリスト内のクリックイベントを処理する（イベント移譲）
 *
 * NOTE: タスクリストの削除・完了切り替えを action に応じて実行する
 * @param {MouseEvent} event - クリックイベントのオブジェクト
 */
function handleTaskListClick(event) {
  // クリックされた要素の data-id と data-action を取得
  const { id, action } = event.target.dataset;

  // idが存在しない場合は何もしない
  if (!id) return;

  // actionに応じたAPI呼び出しを実行する
  if (action === 'delete') {
    apiCall(() => deleteTask(id));
  } else if (action === 'toggle') {
    apiCall(() => toggleTask(id, event.target.checked));
  }
}

// ==========================================
// イベントリスナー
// ==========================================

// --- タスク入力欄 ---
taskForm.addEventListener('submit', handleTaskSubmit);

// --- タスクリストの削除・完了切り替え（イベント移譲）---
taskList.addEventListener('click', handleTaskListClick);

// ==========================================
// 初期表示（ページ読み込み時にAPIから一覧取得）
// ==========================================

apiCall(fetchTasks);
```

ここまでの内容で、画面と API がつながったタスク管理アプリが完成しました。各章で学んだことを振り返っておきます。

| 章 | テーマ | 学んだこと |
|----------|--------|-----------|
| 入門03 | オリジン | フロント/バック分離構成 / 同一オリジンポリシー / CORS エラーの読み方 |
| 入門04 | つなぐ | `CORSMiddleware`（サーバー側が許可を宣言する）/ `fetch` + `async` / `await` / 正しいデータの置き場所がサーバーへ移る |
| 入門05 | CRUD の通信化 | POST / PUT / DELETE と `Content-Type` / `JSON.stringify` / 「書いたら取り直す」同期 / 部分更新 |
| 入門06 | 通信する画面の作法 | ローディング・エラーの表示 / `finally` / 高階関数による `try` / `catch` の一元化 |

前作の画面の「**状態 → 描画 → イベント**」の骨格は、**そのまま**残っています。変わったのは、状態の置き場所が `localStorage` からサーバーに移ったことだけです。

React や Vue などのフレームワークを使ったアプリでも、画面と API をつなぐ考え方（別オリジンと CORS、非同期の通信、サーバーを正とする同期、ローディングとエラーの表示）は同じです。この書籍で作った原型が、きっと役に立つはずです。
