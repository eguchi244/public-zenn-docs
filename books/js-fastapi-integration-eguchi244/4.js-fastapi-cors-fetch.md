# CORS設定と一覧取得
第4章では、API に CORS の設定を追加して画面とつなぎ、API から取得したタスク一覧を画面に表示します（Phase 2）。

# 今回の目標物
- 画面を開いても、コンソールに CORS エラーが**出ない**
- Swagger UI で作ったタスクが、画面の一覧に表示される
- 開発者ツールの Network タブで、`GET /tasks` のリクエストとレスポンス（JSON）が見える

完成すると次の画面になります。Swagger UI の `POST /tasks` でタスクを2件作ってから、画面をリロードしたところです。画面では何も追加していないのに2件並び、件数も「残り 2 件 / 全 2 件」になっていれば、API から一覧を取得できています。追加・完了切り替え・削除の操作は、まだ API につながっていません（入門05）。

# ①API に CORS の設定を追加する
`backend/main.py` に `CORSMiddleware` を追加します。

まず、ファイル冒頭の説明を統合版に変え、import を1行足します。

```python:backend/main.py

タスク管理API（フロント・バック統合版）
"""
```

```python:backend/main.py

```

次に、エンドポイントのセクションの先頭にあった `app = FastAPI(...)` を独立したセクションへ移し、その直後にミドルウェアを登録します。

```python:backend/main.py
# ==========================================
# エントリーポイント・CORS設定
# ==========================================

app = FastAPI(title="タスク管理API（統合版）", version="1.0.0")

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://127.0.0.1:5500",  # Live Server（IPアドレス形式）
        "http://localhost:5500",  # Live Server（ホスト名形式）— ブラウザによって異なるため両方指定
        "http://127.0.0.1:5510",  # 開発機によっては5500がOSにブロックされるため代替ポートも許可
        "http://localhost:5510",
    ],
    allow_methods=["*"],
    allow_headers=["*"],
)

# ==========================================
# エンドポイント
# ==========================================
```

**ミドルウェア**は、すべてのリクエストとレスポンスの通り道に挟まる処理です。`CORSMiddleware` は、許可したオリジンからのリクエストに対して、レスポンスに `Access-Control-Allow-Origin` ヘッダーを付けます。入門03のエラーメッセージに出ていた、あのヘッダーです。

## allow_origins は完全一致
`allow_origins` は**完全一致**で照合されます。`127.0.0.1` と `localhost` はブラウザにとって別のオリジンなので、**両方**書きます。

`allow_origins=["*"]`（すべて許可）でも動きますが、「どこからのアクセスを許すか」を明示するのが本来の姿です。

:::message
開発機によっては、Live Server の 5500 番ポートが使えないことがあります。その場合は VS Code の設定（`liveServer.settings.port`）でポートを 5510 番に変えて起動してください。5510 番も許可してあるので、そのまま通信できます。
:::

## つながったことを確かめる
`main.py` を保存すると、`--reload` によって API が自動で再起動します。Live Server の画面をリロードすると、今度はコンソールにタスク一覧（空の配列 `[]`）が表示されるはずです。

# ③一覧を取得して描画する
## ブラウザとサーバーの往復
コードを書く前に、この構成で「一覧を表示する」だけでも何が起きるのかを押さえておきます。前作の画面は、すべてブラウザの中で完結していました。今回は**ブラウザとサーバーの往復**が入ります。

```
[ブラウザ] ページ読み込み → script.js が実行され fetchTasks() が呼ばれる
    │
    │  GET /tasks （HTTPリクエスト）
    ▼
[FastAPIサーバー] read_tasks() が呼ばれる → DBから全件取得
    │
    │  タスク一覧のJSON（HTTPレスポンス）
    ▼
[ブラウザ] await fetch の続きが再開 → res.json() でJSONを配列に戻す
         → render(tasks) で画面に描画
```

通信には時間がかかるため、`fetch` は「結果が届いたら続きを実行する」**非同期**の関数です。入門05で追加する書き込みの操作も、すべて「**操作 → HTTP で送る → 成功したらもう一度一覧を取得して描画**」という同じ往復の形になります。

## script.js を書き直す
入門03で書いた `frontend/script.js` を、次のコードに置き換えます。前作の `createTaskElement` / `render` を活かしつつ、データの入口を API に差し替えます。上から順に貼っていってください。

```js:frontend/script.js
/* ==========================================
 * タスク管理アプリ（API連携版）
 * fetchによるAPI通信・DOM描画・通信UI（ローディング/エラー表示）
 * ========================================*/
```

### 型定義
```js:frontend/script.js
// ==========================================
// 型定義
// ==========================================

/**
 * APIが返すタスク1件
 *
 * @typedef {Object} Task
 * @property {number} id - タスクのID（DBが採番する）
 * @property {string} title - タスクの内容
 * @property {boolean} completed - 完了していれば true
 * @property {string} created_at - 作成日時（APIが返す日時の文字列）
 */
```

型定義を、**API が実際に返す形**に合わせます。前作との違いは2つです。

- `id` が文字列から数値に変わる（UUID の文字列 → SQLite の自動採番の整数）
- 作成日時が `createdAt` から `created_at` に変わる

JSON のキー名はデータを持っている側（サーバー）の命名にそのまま従うため、JavaScript の慣習（camelCase）ではなく、Python の慣習（snake_case）になります。

### 一覧を取得する ― fetchTasks
```js:frontend/script.js
// ==========================================
// API通信
// ==========================================

/**
 * APIからタスク一覧を取得して画面に描画する
 *
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function fetchTasks() {
  // FastAPIからタスク一覧を取得
  const res = await fetch(`${API_BASE}/tasks`);

  // レスポンス結果を判定
  // NOTE: fetchは404や500でも例外にならずres.okがfalseになるだけなので、自分で例外に変換する必要がある
  if (!res.ok) throw new Error(`GET /tasks failed: ${res.status}`);

  // JSONをTasks配列に変換
  /** @type {Task[]} */
  const tasks = await res.json();

  // 画面を再描画
  render(tasks);
}
```

#### async / await
`fetch` は、結果を **Promise**（「あとで結果が届く」ことを表すオブジェクト）で返す非同期の関数です。`await` を付けると、結果が届くまでその関数の続きを待ってから、次の行へ進みます。

`await` を使える関数には `async` を付けます。`await` で待っている間も、ブラウザが固まることはありません。

#### res.ok を自分で確かめる
`fetch` は、404 や 500 のような**失敗のステータスコードが返っても例外になりません**。例外になるのは、サーバーにつながらないなど、通信そのものが失敗したときだけです。

ステータスコードが 200 番台なら `res.ok` が `true`、それ以外なら `false` になるので、`false` のときは自分で `throw` して例外に変えます。投げた例外は、入門06で作る `apiCall` が受け止めます。

#### res.json()
レスポンスの本文（JSON の文字列）を、JavaScript の配列やオブジェクトに戻します。これも非同期なので `await` を付けます。

### 描画 ― createTaskElement と render
```js:frontend/script.js
// ==========================================
// DOM 描画
// ==========================================

/**
 * タスクリストのli要素を作成する
 *
 * @param {Task} task - タスク
 * @returns {HTMLLIElement}　li要素のタスクリスト
 */
function createTaskElement(task) {
  // li要素を作成する
  const li = document.createElement('li');
  li.className = task.completed ? 'task-item completed' : 'task-item';

  // checkbox要素を作成する
  const checkbox = document.createElement('input');
  checkbox.type = 'checkbox';
  checkbox.checked = task.completed;
  checkbox.dataset.id = task.id;
  checkbox.dataset.action = 'toggle';

  // タイトルのspan要素を作成する
  const title = document.createElement('span');
  title.className = 'task-title';
  title.textContent = task.title; // XSS対策(textContent使用)

  // 削除用のbtn要素を作成する
  const deleteBtn = document.createElement('button');
  deleteBtn.type = 'button';
  deleteBtn.className = 'btn btn-delete';
  deleteBtn.textContent = '削除';
  deleteBtn.dataset.id = task.id;
  deleteBtn.dataset.action = 'delete';

  // li要素に各要素をまとめて追加する
  li.append(checkbox, title, deleteBtn);
  return li;
}
```

`createTaskElement()` は前作のまま変わりません。タスク1件の形（`id`・`title`・`completed`）が同じなので、そのまま使えます。

```js:frontend/script.js
/**
 * APIから取得したタスク一覧で画面を再描画する
 *
 * NOTE: フロントは状態を持たないため、描画対象は状態変数ではなく引数で受け取る
 *
 * @param {Task[]} tasks - APIから取得したタスク一覧
 */
function render(tasks) {
  // タスクリストの再描画（空にしてから生成し直す）
  taskList.innerHTML = '';
  tasks.forEach((task) => {
    taskList.appendChild(createTaskElement(task));
  });

  // フッター（残り件数 / 総件数）
  const remaining = tasks.filter((task) => !task.completed).length;
  taskCount.textContent = `残り ${remaining} 件 / 全 ${tasks.length} 件`;
}
```

# ④状態の置き場所が変わった
前作との**いちばん大きな違い**は、`render()` の形に表れています。

前作では、`tasks` 配列が画面の状態変数でした。タスクの正しい姿を知っているのは、ブラウザの中の配列（とその保存先の `localStorage`）でした。

この書籍では、**タスクの正しい姿を知っているのはサーバー（データベース）だけ**です。これを「単一の真実のソース（Single Source of Truth）がサーバーに移った」と言います。

- フロントは `tasks` を変数として持たない
- `render(tasks)` は、描くものを**引数で受け取る**
- フロントの仕事は「サーバーから取得して描く」だけになる

前作にあった `let tasks = []`・`filter`・`localStorage` まわりの処理は、すべて不要になりました。

:::message
データベースを共有しているので、Swagger UI（`/docs`）から作ったタスクも、画面の一覧に表示されます。画面と Swagger UI は、同じデータを別の窓口から見ているだけです。
:::

:::details backend/main.py の全体コード
```python:backend/main.py
"""
タスク管理API（フロント・バック統合版）
"""
from datetime import datetime, timezone

from fastapi import Depends, FastAPI, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel, ConfigDict, Field
from sqlalchemy import Boolean, Column, DateTime, Integer, String, create_engine
from sqlalchemy.orm import Session, declarative_base, sessionmaker

# ==========================================
# DB設定（SQLite）
#
# NOTE: SQLiteは既定で「作成したスレッドからのみ利用可」だが無効にすること!!
# FastAPIはリクエストごとに別スレッドで処理するため、"check_same_thread": False を指定する必要がある
# ==========================================

DATABASE_URL = "sqlite:///./tasks.db"
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine)
Base = declarative_base()

class TaskModel(Base):
    __tablename__ = "tasks"

    id = Column(Integer, primary_key=True, index=True)
    title = Column(String(255), nullable=False)
    completed = Column(Boolean, default=False)
    created_at = Column(DateTime, default=lambda: datetime.now(timezone.utc))

# 起動時にテーブルを自動生成
Base.metadata.create_all(bind=engine)

# ==========================================
# Pydanticモデル
# ==========================================

class TaskCreate(BaseModel):
    """タスク作成時のリクエストモデル"""
    title: str = Field(..., min_length=1, max_length=255)
    completed: bool = False

class TaskUpdate(BaseModel):
    """タスク更新時のリクエストモデル"""
    title: str | None = Field(None, min_length=1, max_length=255)
    completed: bool | None = None

class Task(BaseModel):
    """タスク情報のレスポンスモデル"""
    id: int
    title: str
    completed: bool
    created_at: datetime

    # DBから取得したデータをそのままPydanticのモデルでも変換を許可する
    model_config = ConfigDict(from_attributes=True)

# ==========================================
# 依存関数
# ==========================================

def get_db():
    """
    データベースセッションを生成・管理する依存関数

    リクエストごとに新しいセッションを作成して、API処理の終了後に
    成否を問わず必ずセッションをクローズ（切断）します。

    Returns:
        DB操作のためのセッションオブジェクト（API処理の終了後に閉じる）
    """
    # セッション（接続窓口）を新しく作成する
    db = SessionLocal()
    try:
        # 作成したセッションを呼び出し元に渡し、処理が終わるまで待機する
        yield db
    finally:
        # 正常終了・エラー発生に関わらず、必ずセッションを閉じる
        db.close()

# ==========================================
# ヘルパー関数
# ==========================================

def get_task(task_id: int, db: Session) -> TaskModel:
    """
    指定されたIDのタスクを取得する

    Args:
        task_id : 検索対象のタスクID
        db      : DB操作のためのセッションオブジェクト

    Returns:
        見つかったタスクオブジェクト

    Raises:
        HTTPException : タスクが見つからない場合（404 Task Not Found）。
    """
    task = db.get(TaskModel, task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="Task not found")
    return task

# ==========================================
# エントリーポイント・CORS設定
# ==========================================

app = FastAPI(title="タスク管理API（統合版）", version="1.0.0")

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://127.0.0.1:5500",  # Live Server（IPアドレス形式）
        "http://localhost:5500",  # Live Server（ホスト名形式）— ブラウザによって異なるため両方指定
        "http://127.0.0.1:5510",  # 開発機によっては5500がOSにブロックされるため代替ポートも許可
        "http://localhost:5510",
    ],
    allow_methods=["*"],
    allow_headers=["*"],
)

# ==========================================
# エンドポイント
# ==========================================

@app.get("/tasks", response_model=list[Task])
def read_tasks(completed: bool | None = None, db: Session = Depends(get_db)):
    """
    タスク一覧（?completed=true/false で絞り込み可）

    Args:
    - completed: 完了状態での絞り込み（省略時は全件）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - タスク一覧（ID順のJSON配列）
    """
    query = db.query(TaskModel)

    # 絞り込みがある場合（?completed=true/false）はcompletedが一致するものだけ格納する　
    # NOTE: 絞り込みがない場合（?completed=None, 省略）はこの処理をスキップして全リストを返す
    if completed is not None:
        query = query.filter(TaskModel.completed == completed)

    # タスク一覧をID順に並び変えて返す
    return query.order_by(TaskModel.id).all()

@app.get("/tasks/{task_id}", response_model=Task)
def read_task(task_id: int, db: Session = Depends(get_db)):
    """
    タスク１件を取得

    Args:
    - task_id: 取得対象のタスクID
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - タスク1件（JSON）

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    return get_task(task_id, db)

@app.post("/tasks", response_model=Task, status_code=201)
def create_task(payload: TaskCreate, db: Session = Depends(get_db)):
    """
    タスクを新規作成

    Args:
    - payload: 検証済みの入力（不正な入力は422）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 登録したタスク（201）
    """
    task = TaskModel(title=payload.title, completed=payload.completed)
    db.add(task)
    db.commit()
    db.refresh(task)
    return task

@app.put("/tasks/{task_id}", response_model=Task)
def update_task(task_id: int, payload: TaskUpdate, db: Session = Depends(get_db)):
    """
    タスクを更新（渡された項目のみ反映する部分更新）

    Args:
    - task_id: 更新対象のタスクID
    - payload: 検証済みの入力（None の項目は変更しない。不正な入力は422）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 更新したタスク

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    task = get_task(task_id, db)

    if payload.title is not None:
        task.title = payload.title
    if payload.completed is not None:
        task.completed = payload.completed

    db.commit()
    db.refresh(task)
    return task

@app.delete("/tasks/{task_id}")
def delete_task(task_id: int, db: Session = Depends(get_db)):
    """
    タスクを削除

    Args:
    - task_id: 削除対象のタスクID
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 削除できたことを示す {"ok": true}

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    task = get_task(task_id, db)
    db.delete(task)
    db.commit()
    return {"ok": True}
```

```js:frontend/script.js
/* ==========================================
 * タスク管理アプリ（API連携版）
 * fetchによるAPI通信・DOM描画・通信UI（ローディング/エラー表示）

 * APIが返すタスク1件

 * @property {string} title - タスクの内容
 * @property {boolean} completed - 完了していれば true
 * @property {string} created_at - 作成日時（APIが返す日時の文字列）
 */

// ==========================================
// APIのベースURL
// ==========================================

/** APIサーバーのURL */
const API_BASE = 'http://localhost:8000';

// ==========================================
// DOM要素
// ==========================================

/** 通信中の表示 */
const loading   = document.getElementById('loading');
/** エラーメッセージの表示欄 */
const errorBox  = document.getElementById('error');
/** タスクの入力フォーム */
const taskForm  = document.getElementById('taskForm');
/** タスクの入力欄 */
const taskInput = document.getElementById('taskInput');
/** タスクの一覧を表示する要素 */
const taskList  = document.getElementById('taskList');
/** 残り件数と総件数を表示する要素 */
const taskCount = document.getElementById('taskCount');

// ==========================================
// API通信
// ==========================================

/**
 * APIからタスク一覧を取得して画面に描画する
 *
 * @throws {Error} レスポンスが失敗ステータス（res.okがfalse）の場合
 */
async function fetchTasks() {
  // FastAPIからタスク一覧を取得
  const res = await fetch(`${API_BASE}/tasks`);

  // レスポンス結果を判定
  // NOTE: fetchは404や500でも例外にならずres.okがfalseになるだけなので、自分で例外に変換する必要がある
  if (!res.ok) throw new Error(`GET /tasks failed: ${res.status}`);

  // JSONをTasks配列に変換
  /** @type {Task[]} */
  const tasks = await res.json();

  // 画面を再描画
  render(tasks);
}

// ==========================================
// DOM 描画
// ==========================================

/**
 * タスクリストのli要素を作成する
 *
 * @param {Task} task - タスク
 * @returns {HTMLLIElement}　li要素のタスクリスト
 */
function createTaskElement(task) {
  // li要素を作成する
  const li = document.createElement('li');
  li.className = task.completed ? 'task-item completed' : 'task-item';

  // checkbox要素を作成する
  const checkbox = document.createElement('input');
  checkbox.type = 'checkbox';
  checkbox.checked = task.completed;
  checkbox.dataset.id = task.id;
  checkbox.dataset.action = 'toggle';

  // タイトルのspan要素を作成する
  const title = document.createElement('span');
  title.className = 'task-title';
  title.textContent = task.title; // XSS対策(textContent使用)

  // 削除用のbtn要素を作成する
  const deleteBtn = document.createElement('button');
  deleteBtn.type = 'button';
  deleteBtn.className = 'btn btn-delete';
  deleteBtn.textContent = '削除';
  deleteBtn.dataset.id = task.id;
  deleteBtn.dataset.action = 'delete';

  // li要素に各要素をまとめて追加する
  li.append(checkbox, title, deleteBtn);
  return li;
}

/**
 * APIから取得したタスク一覧で画面を再描画する
 *
 * NOTE: フロントは状態を持たないため、描画対象は状態変数ではなく引数で受け取る
 *
 * @param {Task[]} tasks - APIから取得したタスク一覧
 */
function render(tasks) {
  // タスクリストの再描画（空にしてから生成し直す）
  taskList.innerHTML = '';
  tasks.forEach((task) => {
    taskList.appendChild(createTaskElement(task));
  });

  // フッター（残り件数 / 総件数）
  const remaining = tasks.filter((task) => !task.completed).length;
  taskCount.textContent = `残り ${remaining} 件 / 全 ${tasks.length} 件`;
}

// ==========================================
// 初期表示（ページ読み込み時にAPIから一覧取得）
// ==========================================

fetchTasks();
```

# まとめ
ここまでの内容で、画面と API がつながり、API のタスク一覧を画面に表示できました。

- `CORSMiddleware` で、サーバー側が許可するオリジンを宣言する
- `fetch` と `async` / `await` で、HTTP リクエストを送って結果を待つ
- `fetch` は失敗のステータスでも例外にならないので、`res.ok` を自分で確かめる
- 正しいデータの置き場所がサーバーに移り、フロントは「取得して描く」だけになる
