# 2つのプロジェクトを合流させる
第3章では、前作の画面と API を1つのフォルダに合流させ、それぞれを起動します（Phase 1）。そのうえで、画面から API を呼び出し、**わざと「つながらない」ことを確かめます**。

# 今回の目標物
- `backend/` と `frontend/` に分かれたフォルダ構成ができている
- API が `http://localhost:8000` で動き、Swagger UI が開ける
- Live Server で開いた画面から API を呼ぶと、開発者ツールのコンソールに **CORS エラー**が出る（この章では出るのが正解）

# ①出発点のコードを用意する
フロントエンドとバックエンドを独立したプロセスとして動かすため、フォルダも分けて次の構成にします。

```
js-fastapi-task/
├── backend/      ← 前作の API の完成版
│   ├── main.py
│   └── requirements.txt
└── frontend/     ← 前作の画面の完成版
    ├── index.html
    ├── style.css
    └── script.js
```

この構成にした出発点のコードを、答え合わせ用のリポジトリに用意しています。次のどちらかの方法で取得してください。

## Git で取得する
任意の場所で PowerShell を開き、次のコマンドを実行します。`js-fastapi-task` フォルダが作られます。

```powershell:PowerShell
git clone -b Start/出発点のコード https://github.com/eguchi244/JS-FastAPI-Integration-Tutorial-PJ.git js-fastapi-task
```

## ZIP で取得する
Git を使わない場合は、下記のページを開き、「Code」→「Download ZIP」でダウンロードします。展開したフォルダの名前を `js-fastapi-task` に変えてください。

https://github.com/eguchi244/JS-FastAPI-Integration-Tutorial-PJ/tree/Start/出発点のコード

:::message
前作の2冊を最後まで進めた方は、**自分で書いたコードを使ってもかまいません**。上の構成になるように、API の `main.py`・`requirements.txt` を `backend/` へ、画面の `index.html`・`style.css`・`script.js` を `frontend/` へコピーしてください。前作の `tasks.db` と `venv/` はコピーしません。
:::

取得したら、VS Code で `js-fastapi-task` フォルダを開きます。

# ②API を起動する
VS Code のターミナル（PowerShell）で `backend/` に移動し、仮想環境を作ってライブラリをインストールし、API を起動します。

```powershell:PowerShell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
uvicorn main:app --reload
```

:::message
「このシステムではスクリプトの実行が無効になっているため」というエラーになる場合は、初回だけ次のコマンドを実行してから、もう一度仮想環境を有効にしてください。

```powershell:PowerShell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```
:::

ブラウザで `http://localhost:8000/docs` を開き、Swagger UI が表示されれば起動できています。`tasks.db` はまだ無いので、起動時に空のデータベースが新しく作られます。

:::message
API はこのターミナルで動かしたままにします。以降、API を止めるのは `Ctrl + C`、もう一度起動するのは `uvicorn main:app --reload` です（仮想環境を有効にした `backend/` で実行します）。
:::

# ③まず「つながらない」ことを体験する
`frontend/script.js` を、いったん**中身を全部消して**次のコードだけにします。前作のコードは入門04で書き直すので、消してしまってかまいません。

```js:frontend/script.js
/** APIサーバーのURL */
const API_BASE = 'http://localhost:8000';

/**
 * APIからタスク一覧を取得し、コンソールに表示する（通信の動作確認）
 */
async function main() {
  const res = await fetch(`${API_BASE}/tasks`);
  console.log(await res.json());
}

main();
```

`fetch` はブラウザから HTTP リクエストを送る関数です。ここでは「`GET /tasks` を呼んで、返ってきた JSON をコンソールに出す」だけを試しています。`async` / `await` の意味は入門04で説明します。

`index.html` は変更しません。VS Code のエクスプローラーで `frontend/index.html` を右クリック →「Open with Live Server」で開いてください。

開発者ツール（F12）の Console を開くと、**赤い CORS エラーが出ているはずです。**

```
Access to fetch at 'http://localhost:8000/tasks' from origin 'http://127.0.0.1:5500'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present...
```

続けて `Uncaught (in promise) TypeError: Failed to fetch` も出ますが、これは上の CORS のブロックによって `fetch` が失敗した、という同じ原因の表示です。

# ④何が起きたのか ― オリジンと CORS
## オリジンとは
**オリジン**は、「プロトコル・ホスト・ポート」の3つの組です。3つのうちどれか1つでも違えば、別のオリジンになります。

| | プロトコル | ホスト | ポート |
|---|-----------|--------|--------|
| 画面（Live Server） | `http` | `127.0.0.1` | `5500` |
| API（Uvicorn） | `http` | `localhost` | `8000` |

画面と API は、ホストの書き方もポートも違うので、**別のオリジン**です。

## 同一オリジンポリシー
ブラウザは、**同一オリジンポリシー**により、JavaScript から別のオリジンへの通信を既定でブロックします。

たとえば、悪意のあるサイトの JavaScript が、あなたがログインしている銀行サイトへ勝手にリクエストを送り、結果を読み取れてしまったら大変です。これを防ぐための、ブラウザの安全装置です。

:::message
ブロックしているのは**サーバーではなくブラウザ**です。Swagger UI（`/docs`）は API と同じオリジンから配信されているので、問題なく API を呼べます。
:::

## CORS ― サーバーが「許可」を宣言する
別オリジンからの通信を通すには、**サーバー側が**「このオリジンからのアクセスは許可する」と、レスポンスのヘッダーで宣言する必要があります。この仕組みが **CORS**（Cross-Origin Resource Sharing）です。

エラーメッセージの `No 'Access-Control-Allow-Origin' header is present` は、「API のレスポンスに許可のヘッダーが無かったので、ブラウザが結果を捨てた」という意味です。次の入門04で、FastAPI にこのヘッダーを付けさせます。

# ⑤動作確認
次の状態になっていれば、この章は完了です。

- [✔] `http://localhost:8000/docs` で Swagger UI が開ける（前作と同じ画面）
- [✔] Live Server で画面を開くと、コンソールに **CORS エラー**が出る（この時点では出るのが正解です）

:::details frontend/script.js の全体コード
```js:frontend/script.js
/** APIサーバーのURL */
const API_BASE = 'http://localhost:8000';

/**
 * APIからタスク一覧を取得し、コンソールに表示する（通信の動作確認）
 */
async function main() {
  const res = await fetch(`${API_BASE}/tasks`);
  console.log(await res.json());
}

main();
```
:::

# まとめ
ここまでの内容で、前作の画面と API を1つのフォルダに合流させ、それぞれを起動できました。

- 画面（Live Server）と API（Uvicorn）は、別々のプロセス・別々のオリジンで動く
- ブラウザは同一オリジンポリシーにより、別オリジンへの通信をブロックする
- 通信を通すには、サーバー側が CORS で許可を宣言する必要がある

「つながらない」ことと、その理由が分かりました。次の入門04では、API に CORS の設定を追加し、画面にタスク一覧を表示します。
