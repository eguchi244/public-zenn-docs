# ③状態設計
## 状態設定値
アプリが覚えておく値（状態）は次のとおりです。画面はすべて、この状態から作ります。

```
タイマー状態
  mode        : 'countdown' | 'stopwatch'
  status      : 'idle' | 'running' | 'paused' | 'finished'
  intervalId  : number | null   ← setInterval の返り値
  startTime   : number | null   ← 開始/再開時の Date.now() スナップショット（ドリフト補正用）
  elapsedSec  : number          ← ストップウォッチ用（経過秒数）
  remainingSec: number          ← カウントダウン用（残り秒数）
  targetSec   : number          ← カウントダウン設定値（リセット基準）
  laps        : number[]        ← ラップ時点の elapsedSec 一覧
```

:::message
`setInterval` は JavaScript のイベントループの遅延により、指定した間隔より遅く発火することがあります。秒数を1ずつ足していく方式だと、長時間動かしたときにずれが積み重なります。そのため `startTime` に `Date.now()` を保存し、`tick()` の中では毎回 `Date.now() - startTime` から計算し直します（入門04で詳しく扱います）。

あわせて発火間隔は **500ms**（`setInterval(tick, 500)`）とします。1000ms にすると、発火の遅れがそのまま表示の「1秒飛び」として見えてしまうためです。秒の切り替わりより短い間隔で確認することで、表示を追従させます。表示・計算はどちらも秒単位なので、500ms 間隔でも表示が変わるのは1秒ごとです。
:::

## ステータスに応じたボタンと入力欄の状態
| status | 開始ボタン | 停止ボタン | リセットボタン | ラップボタン<br>※1 | 入力欄<br>※2 |
|--------|------|------|--------|--------|--------|
| `'idle'` | 有効<br>※3 | 無効 | 無効 | 無効 | 有効 |
| `'running'` | 無効 | 有効 | 有効 | 有効 | 無効 |
| `'paused'` | 有効  | 無効 | 有効 | 無効 | 無効 |
| `'finished'`  | 無効 | 無効 | 有効 | ―<br>※1 | 無効 |

- **※1 ラップボタン:** ストップウォッチ専用です。`state.mode === 'stopwatch'` のときだけ `disabled` を更新します。カウントダウンでは `'finished'` を含め `disabled` を更新しないため、ストップウォッチ計測中にタブを切り替えると有効のまま残りますが、ラップの領域（`#lapControls`）ごと非表示になるため画面には現れません
- **※2 入力欄:** カウントダウン専用（`#countdownInput`）です。ストップウォッチでは非表示にするため `disabled` は制御しません
- **※3 `'idle'` の開始ボタン:** カウントダウンで `targetSec === 0`（時間未設定）のときは、`idle` でも**無効**です。そのため初期表示（`index.html` の `disabled` 属性付き）では開始できず、時間を入力して `targetSec` が 0 以外になった時点で有効になります。ストップウォッチは `idle` なら常に有効です

# ④イベント設計
「どの要素が、どの操作で、何をするか」の一覧です。

| 要素 | イベント | 処理 |
|------|----------|------|
| タブボタン | click | モード切り替え・状態リセット・表示切り替え |
| 開始ボタン | click | タイマー開始 / 再開 |
| 停止ボタン | click | タイマー一時停止 |
| リセットボタン | click | タイマーリセット |
| ラップボタン | click | 現在の elapsedSec をラップ一覧に追加・表示更新 |
| 時間入力（カウントダウン） | input / change | 入力値を範囲補正（クランプ）してから targetSec / remainingSec を再計算（input: キー入力ごと・change: フォーカス離脱時） |

# ⑤主要処理フロー
## カウントダウン 開始
```
[開始ボタン押下]
  → status を 'running' に変更
  → startTime = Date.now() - (targetSec - remainingSec) * 1000 を記録
  → setInterval(tick, 500) を呼び出し intervalId を保存（表示更新は500ms間隔）
  → 通知を非表示にし display の finished クラスを外す（前回のタイムアップ表示をクリア）
  → tick() 内: remainingSec = targetSec - Math.floor((Date.now() - startTime) / 1000)
             → display 更新
  → remainingSec <= 0 のとき clearInterval + status を 'finished' に変更
                          + アラート発火（playBeep() は非同期・await せず呼び出し）
```

:::message
`targetSec === 0`（時間未設定）のときは開始ボタンが無効なうえ、`startTimer()` の先頭でもガードして何もせずに return します。
:::

## ストップウォッチ 開始
```
[開始ボタン押下]
  → status を 'running' に変更
  → startTime = Date.now() - elapsedSec * 1000 を記録（一時停止後の再開に対応）
  → setInterval(tick, 500) を呼び出し intervalId を保存
  → tick() 内: elapsedSec = Math.floor((Date.now() - startTime) / 1000) → display 更新
```

## 停止（共通）
```
[停止ボタン押下]
  → clearInterval(intervalId)
  → intervalId を null に
  → status を 'paused' に変更
```

## リセット（共通）
```
[リセットボタン押下]
  → clearInterval(intervalId)
  → intervalId を null に
  → startTime を null に
  → elapsedSec を 0 に / remainingSec を targetSec に戻す（targetSec は保持する）
  → laps を空配列に
  → status を 'idle' に変更
  → display の finished クラスを外し、通知を非表示にする
  → display / ボタン / ラップ一覧の表示を更新
```

:::message
リセットではカウントダウン設定値（`targetSec`）と入力欄の値は保持します。タイムアップ（`'finished'`）後に同じ設定で再開するには、このリセットで `'idle'` に戻す必要があります（モード切り替えでも `'idle'` に戻りますが、そちらは `targetSec` ごと 0 にクリアされます）。
:::

## モード切り替え（タブ）
```
[タブ押下]
  → 現在と同じモードなら何もせず return
  → mode を切り替え先に変更
  → clearInterval(intervalId) / intervalId・startTime を null に
  → elapsedSec / remainingSec / targetSec を 0 に、laps を空配列に、status を 'idle' に
  → display の finished クラスを外し、通知を非表示にする
  → 押されたタブにだけ active クラスを付与する
  → カウントダウン: 入力欄を表示し値を 0 にリセット、ラップUIを非表示
    ストップウォッチ: 入力欄を非表示、ラップボタンを表示・ラップ一覧は非表示
  → display / ボタンの表示を更新
```

:::message
リセットと違い `targetSec` も 0 に戻します。そのためカウントダウンへ切り替えた直後は時間未設定となり、開始ボタンは無効な状態から始まります。
:::

## カウントダウン時間の入力
```
[時/分/秒の入力欄を操作]
  → status が 'idle' 以外なら何もせず return（計測中・一時停止中は変更不可）
  → 3つの入力欄をそれぞれ範囲補正（クランプ）し、補正後の値を入力欄へ書き戻す
  → targetSec = h * 3600 + m * 60 + s
  → remainingSec = targetSec
  → display 更新
  → ボタン更新（targetSec が 0 → 非0 で開始ボタンが有効になる）
```

### 入力値の範囲
| 入力欄 | id | 範囲 | HTML属性 |
|--------|-----|------|----------|
| 時 | `inputH` | 0〜99 | `type="number" min="0" max="99" value="0"` |
| 分 | `inputM` | 0〜59 | `type="number" min="0" max="59" value="0"` |
| 秒 | `inputS` | 0〜59 | `type="number" min="0" max="59" value="0"` |

設定可能な最大値は `99:59:59`（= 359,999秒）です。

### クランプの仕様
| 入力 | 補正後 |
|------|--------|
| 空欄・数値として解釈できない文字列 | 最小値（`0`） |
| 最小値未満（負値など） | 最小値（`0`） |
| 最大値超過（例: 秒に `90`） | 最大値（`59`） |
| 小数（例: `1.9`） | 整数部（`parseInt` により `1`） |
| 範囲内の整数 | そのまま |

:::message
**HTMLの `min` / `max` だけで足りない理由:** `type="number"` の `min` / `max` は、スピナー操作とフォーム送信時の検証にしか効きません。キーボードで直接 `90` と打ち込んだ値はそのまま保持されます。このアプリはフォーム送信を行わないため、JavaScript 側で必ずクランプします。

**エラー表示をしない理由:** 補正結果を入力欄へ即座に書き戻すことで、ユーザーは確定した値を常に画面上で確認できます。学習用途のため、エラーメッセージのUIは設けません。
:::

# ⑦完成コードの全体構造
完成版の `script.js` は、次の順番で並びます。入門03以降は、この部品を少しずつ作っていく作業です。

```
script.js
│
├── DOM参照                     ← getElementById を最初に一括取得
├── state オブジェクト          ← アプリの全状態を1箇所で管理
│
├── formatTime()                ← 秒数 → HH:MM:SS 変換
├── tick()                      ← 500ms ごとに呼ばれる。時間計算と終了判定
├── playBeep()                  ← Web Audio API でビープ音（入門05・async/await）
│
├── updateDisplay()             ← state を見て表示を更新
├── updateButtons()             ← state を見てボタン・入力・ラップの有効/無効を更新
├── updateLapList()             ← state.laps を見てラップ一覧を再描画（入門05）
│
├── onCountdownFinished()       ← タイムアップ時の通知・アニメーション・音（入門05）
│
├── startTimer()                ← 開始ボタンの処理
├── stopTimer()                 ← 停止ボタンの処理
├── resetTimer()                ← リセットボタンの処理
├── addLap()                    ← ラップボタンの処理（入門05）
├── switchMode()                ← タブ切り替えの処理（入門04）
├── onInputChange()             ← カウントダウン時間入力の処理（入門04）
│
└── イベントリスナー登録 + 初期描画
```

# まとめ
ここまでで、画面・状態・イベント・処理の流れという「設計」がそろいました。

特に大切なのは「状態設計」です。このアプリでは、画面の見た目はすべて状態（`state`）から作ります。ボタンの有効/無効も、表示される時間も、状態を見て決めます。この考え方は入門03から一貫して使います。
