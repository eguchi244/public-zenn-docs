# シンプルなストップウォッチを作る
第3章では、最小限の機能だけで動くストップウォッチを作ります（Phase 1）。

# 今回の目標物
カウントダウンもラップもない、1画面のシンプルなストップウォッチです。

- 開始を押すと時間が進む
- 停止を押すと止まり、再び開始を押すと続きから計測できる
- リセットを押すと `00:00:00` に戻る

この章のコードは、この後の章でもそのまま土台になります。特に「状態から画面を作る」という考え方は最後まで使い続けるので、しっかり押さえておきましょう。

# ①HTML マークアップを作る
作業フォルダに `index.html` を作成し、次の内容を書きます。

```html:index.html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>ストップウォッチ</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <div class="app">
    <h1>ストップウォッチ</h1>

    <div id="display" class="display">00:00:00</div>

    <div class="controls">
      <button id="btnStart" class="btn btn-start">開始</button>
      <button id="btnStop"  class="btn btn-stop"  disabled>停止</button>
      <button id="btnReset" class="btn btn-reset" disabled>リセット</button>
    </div>
  </div>

  <script src="script.js"></script>
</body>
</html>
```

ポイントは2つです。

- `disabled` 属性を最初から付けておき、JavaScript から付け外しして有効/無効を制御します
- `<script>` は `</body>` の直前に置きます。HTML は上から読み込まれるため、先に書くと JavaScript が実行された時点ではまだボタンなどの要素が存在せず、`getElementById` が `null` を返してしまいます

:::message
`style.css` は入門01の「CSS について」でダウンロードしたものを、`index.html` と同じフォルダに置いてください。
:::

# ②formatTime 関数を実装する
`script.js` を作成し、最初に「秒数 → HH:MM:SS 文字列」に変換する関数を書きます。

```js:script.js
/* ==========================================
 * ユーティリティ
 * ========================================*/

/**
 * 秒数を HH:MM:SS 文字列に変換する
 *
 * @param {number} totalSec - 変換する秒数（0以上の整数を想定。負値・小数は丸めていない）
 * @returns {string} `00:00:00` 形式の文字列（各桁は2桁に0埋め）
 */
function formatTime(totalSec) {
  const h = Math.floor(totalSec / 3600);
  const m = Math.floor((totalSec % 3600) / 60);
  const s = totalSec % 60;
  return [h, m, s].map(v => String(v).padStart(2, '0')).join(':');
}
```

## 計算の仕組み
3661秒の場合を例に、計算を追ってみます。

```
h = Math.floor(3661 / 3600)        = 1
m = Math.floor((3661 % 3600) / 60) = Math.floor(61 / 60) = 1
s = 3661 % 60                      = 1
→ '01:01:01'
```

## map とアロー関数
`[h, m, s].map(...)` は「配列の各要素に同じ処理を適用して、結果を集めた新しい配列を作る」メソッドです。

渡している `v => String(v).padStart(2, '0')` は**アロー関数**という関数の短縮記法で、`function (v) { return String(v).padStart(2, '0'); }` と同じ意味です（この書籍では以後もこの記法を使います）。

`padStart(2, '0')` は `'5'` → `'05'` のように常に2桁へ揃え、最後の `join(':')` が配列を `:` 区切りで1本の文字列につなぎます（`['01', '01', '01']` → `'01:01:01'`）。

## 動作確認
ブラウザで `index.html` を開き、開発者ツールのコンソール（F12）で `formatTime(3661)` と入力して、`'01:01:01'` が返ることを確認します。

# ③ストップウォッチの開始・停止・リセットを実装する
## まず全体の動きを理解する
ここから書くコードは、**上から順に実行されて終わり、ではありません**。JavaScript のプログラムは次の2段階で動きます。

1. **ページ読み込み時（1回だけ）:** ファイルが上から実行され、「ボタンが押されたらこの関数を呼んでね」という**予約（イベントリスナー登録）**をして待機状態に入る
2. **待機後:** ユーザーがボタンを押すたびに、予約しておいた関数が呼び出される

つまり実際の動きは、すべて「クリック」をきっかけに始まります。全体の流れは次のとおりです。

```
ページ読み込み時（上から1回だけ実行）
  状態変数の初期化 → DOM参照の取得 → 関数の定義 → イベントリスナー登録 → 初期描画
  ここで「待機状態」に入る

以降はユーザーの操作がきっかけ:
  [開始をクリック]     → startTimer() が呼ばれる → tick を1秒ごとに実行するよう予約
  （以降1秒ごと）      → tick() が呼ばれる → 経過秒数 +1 → 表示を更新
  [停止をクリック]     → stopTimer() が呼ばれる → tick の予約を取り消す
  [リセットをクリック] → resetTimer() が呼ばれる → 予約を取り消して 0 秒に戻す
```

この流れを頭に置いて、コードを役割ごとに分けて書いていきます。以下のコードは、②で書いた `formatTime` の後ろに順番に追記していきます。

## (1) DOM参照と状態変数
```js:script.js
/* ==========================================
 * 状態変数
 * ========================================*/
let status     = 'idle'; // 'idle' | 'running' | 'paused'
let intervalId = null;
let elapsedSec = 0;

/* ==========================================
 * DOM参照
 * ========================================*/
const display  = document.getElementById('display');
const btnStart = document.getElementById('btnStart');
const btnStop  = document.getElementById('btnStop');
const btnReset = document.getElementById('btnReset');
```

`document.getElementById('display')` は「HTML の中から `id="display"` の要素を探して取ってくる」命令です。取得した要素は変数に入れておき、以後はこの変数を通じて表示の書き換えやクリックの検知を行います。

続く3つの**状態変数**が、このアプリの本体です。画面はあくまで「状態変数の写し」で、変数を変えてから画面に反映する、という順序で動かします。

| 変数 | 役割 |
|------|------|
| `status` | 今どの状態か（`'idle'`=初期状態 / `'running'`=計測中 / `'paused'`=一時停止中） |
| `intervalId` | 「1秒ごとに実行して」という予約の**予約番号**。停止時に予約を取り消すために必要 |
| `elapsedSec` | 経過秒数。表示はこの値を `formatTime` で変換して作る |

## (2) 状態を画面に反映する関数
```js:script.js
/* ==========================================
 * 表示・ボタン更新
 * ========================================*/
/**
 * 現在の経過秒数を HH:MM:SS 形式で表示欄へ書き出す
 */
function updateDisplay() {
  display.textContent = formatTime(elapsedSec);
}

/**
 * 現在の status に応じて3つのボタンの活性・非活性を切り替える
 */
function updateButtons() {
  btnStart.disabled = (status === 'running');
  btnStop.disabled  = (status !== 'running');
  btnReset.disabled = (status === 'idle');
}
```

どちらも「状態変数を読んで、画面に反映するだけ」の関数です。

- `updateDisplay` は `elapsedSec` を HH:MM:SS 文字列にして表示欄に書き込みます。`textContent` に代入すると、要素の中身のテキストが置き換わります
- `updateButtons` は `status` に応じてボタンの `disabled`（無効化）を付け外しします。`(status === 'running')` は比較の結果（`true` / `false`）をそのまま代入しています。たとえば計測中なら `btnStart.disabled = true` となり、開始ボタンが押せなくなります

3つの状態とボタンの対応は次のとおりです。この表をコードにしたものが `updateButtons` です。

| status | 開始ボタン | 停止ボタン | リセットボタン |
|--------|----------|----------|-------------|
| `'idle'`（初期状態） | 有効 | 無効 | 無効 |
| `'running'`（計測中） | 無効 | 有効 | 有効 |
| `'paused'`（一時停止） | 有効 | 無効 | 有効 |

## (3) 1秒ごとに実行される tick
```js:script.js
/**
 * 経過秒数を1つ進めて表示へ反映する
 *
 * NOTE: setInterval から1秒ごとに呼ばれる
 */
function tick() {
  elapsedSec++;
  updateDisplay();
}
```

「経過秒数を1増やして、表示を更新する」だけの小さな関数です。ここではまだ**定義しているだけ**で、実行はされません。「1秒ごとに `tick` を呼ぶ」仕組みは、次の `startTimer` が作ります。

## (4) 開始・停止・リセット
```js:script.js
/* ==========================================
 * タイマー操作(開始・停止・リセット)
 * ========================================*/

/**
 * 計測を開始・再開する
 */
function startTimer() {
  intervalId = setInterval(tick, 1000);
  status = 'running';
  updateButtons();
}

/**
 * 計測を一時停止する（経過秒数は保持したまま計測だけを止める）
 *
 * NOTE: clearInterval() と intervalId = null; でタイマーを完全に止める
 */
function stopTimer() {
  clearInterval(intervalId);
  intervalId = null;
  status = 'paused';
  updateButtons();
}

/**
 * 計測を止めて初期状態(idle)へ戻す
 *
 * NOTE: clearInterval() と intervalId = null; でタイマーを完全に止める
 * NOTE: elapsedSec = 0; で経過時間をリセット
 * NOTE: updateDisplay() でリセットした経過時間を反映する必要がある
 */
function resetTimer() {
  clearInterval(intervalId);
  intervalId = null;
  status = 'idle';
  elapsedSec = 0;
  updateDisplay();
  updateButtons();
}
```

3つの関数は、どれも同じ型で書かれています。**「タイマーの予約を操作する → 状態変数を書き換える → 画面反映の関数を呼ぶ」**の3段構えです。

- **`startTimer`（開始）:** `setInterval(tick, 1000)` は「1000ms（1秒）ごとに `tick` を呼び続けて」というブラウザへの**予約**です。呼んだ瞬間に `tick` が実行されるわけではなく、1秒後・2秒後・3秒後…に呼ばれ続けます。戻り値は予約番号で、後で取り消すために `intervalId` に保存します
- **`stopTimer`（停止）:** `clearInterval(intervalId)` で予約番号を指定して予約を取り消します。これで `tick` は呼ばれなくなり、時間が止まります。`intervalId = null` に戻すのは「今は予約が無い」ことを変数上でも明示するためです。`elapsedSec` は触らないので、経過秒数は保持されたままです
- **`resetTimer`（リセット）:** 停止に加えて `elapsedSec = 0` で経過秒数も消します。表示を `00:00:00` に戻す必要があるため、`stopTimer` と違って `updateDisplay()` も呼びます

`stopTimer` が `elapsedSec` を残し、`resetTimer` が消す。この差が「一時停止（続きから再開できる）」と「リセット」の違いを生んでいます。

## (5) イベントリスナー登録と初期描画
```js:script.js
/* ==========================================
 * イベントリスナー
 * ========================================*/
btnStart.addEventListener('click', startTimer);
btnStop.addEventListener('click', stopTimer);
btnReset.addEventListener('click', resetTimer);

/* ==========================================
 * 初期描画
 * ========================================*/
updateDisplay();
updateButtons();
```

`btnStart.addEventListener('click', startTimer)` は「開始ボタンがクリックされたら `startTimer` を呼んでね」という予約です。これで、冒頭のフロー図にあった「クリック → 関数が呼ばれる」の接続が完成します。

:::message alert
**よくあるミス:** ここで `startTimer()` と括弧を付けて書くと、「クリック時に呼ぶ関数を渡す」のではなく、**その場で実行**してしまいます。渡すのは関数そのもの（`startTimer`）です。
:::

最後の `updateDisplay()` / `updateButtons()` は、読み込み時に1回だけ実行される**初期描画**です。ページを開いた直後から「表示は `00:00:00`、開始だけ有効」という正しい画面にするために、待機状態に入る前に一度呼んでおきます。

# ④動きを追いかけてみる
書き終えたら、「開始 → 停止 → 再開」したときに何が起きるかを、コードで追ってみてください。

1. **開始をクリック** → `startTimer` が呼ばれる → `status` が `'running'` になり、1秒ごとの `tick` が予約され、`updateButtons` で開始ボタンが無効化される
2. **1秒ごと** → `tick` が呼ばれる → `elapsedSec` が 1, 2, 3... と増え、そのたびに表示が更新される
3. **停止をクリック** → `stopTimer` が呼ばれる → 予約が取り消されて `tick` が止まる。ただし `elapsedSec` はそのまま
4. **再び開始をクリック** → `startTimer` が再び予約を作る → `tick` は残っていた `elapsedSec` に足していくので、続きから計測される

「ボタンを直接操作せず、`status` を変えてから `updateButtons()` を呼ぶ」という一方通行の流れ（**状態から画面を作る**パターン）が、全編を貫いていることを確認してください。画面の見た目は常に状態変数から導かれるため、不具合が起きたときも「状態変数が正しいか」だけを疑えばよくなります。
