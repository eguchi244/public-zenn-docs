# はじめに
この書籍は、Python の Web フレームワーク **FastAPI** で「タスク管理 API」を作ることを目的としています。

API（Web API）は、画面を持たず、プログラムからの問い合わせ（HTTP リクエスト）にデータ（JSON）で答えるサーバーのことです。ブラウザの画面やスマートフォンのアプリは、裏側でこうした API を呼び出してデータを読み書きしています。

タスク管理 API は、API の基本となる「データを作成・取得・更新・削除する（CRUD）」がひととおり詰まった題材です。

- URL と HTTP メソッド（GET / POST / PUT / DELETE）ごとに処理を割り当てる（ルーティング）
- 受け取るデータ・返すデータの形を宣言し、不正な入力を自動で弾く（Pydantic）
- 「存在しない」「入力が正しくない」を HTTP のステータスコード（404 / 422）で伝える
- データベース（SQLite）にデータを保存し、サーバーを再起動しても消えないようにする（SQLAlchemy）

:::message
この書籍は、コードを読み慣れていない方でも進められるように書いています。コードは役割ごとに分けて掲載し、それぞれの直後に「何をしているか・なぜ必要か」を説明します。Python の基本的な文法（変数・関数・リスト・if 文）が分かっていれば進められます。
:::

# ①作るもの
タスクの一覧・1件取得・作成・更新・削除の5本の API（エンドポイント）を持つ、タスク管理 API です。

画面（フロントエンド）は作りません。FastAPI は、書いたコードから API の説明書兼お試し画面（**Swagger UI**）を自動で作ってくれるので、動作確認はすべてこの画面から行います。完成版の Swagger UI は次のとおりです。

## 機能一覧
### タスクの CRUD
| # | メソッド | URL | 要件 |
|---|----------|---------------|------|
| F-01 | GET | `/tasks` | タスク一覧を ID の昇順で返す。`completed` で完了 / 未完了に絞り込める |
| F-02 | GET | `/tasks/{id}` | 指定 ID のタスクを1件返す（存在しない場合は 404） |
| F-03 | POST | `/tasks` | 新しいタスクを作成して返す |
| F-04 | PUT | `/tasks/{id}` | 指定 ID のタスクを更新して返す。送られた項目だけを書き換える**部分更新**とし、省略された項目は変えない（存在しない場合は 404） |
| F-05 | DELETE | `/tasks/{id}` | 指定 ID のタスクを削除する（存在しない場合は 404） |

### タスクのデータ項目
| 項目 | 型 | 説明 |
|------|----|------|
| `id` | int | タスクを一意に識別する ID。作成時にサーバー側で自動で振る |
| `title` | str | タスクの内容。作成時は必須 |
| `completed` | bool | 完了フラグ。作成時に省略した場合は `false` |
| `created_at` | datetime | 作成日時（UTC）。サーバー側で記録し、クライアントからは指定できない |

### 入力チェック（バリデーション）
| # | 要件 |
|---|------|
| F-06 | タスク作成時、`title` は必須・空文字不可 |
| F-07 | 作成時・更新時、`title` は 255 文字以内 |
| F-08 | 入力チェックに違反したときは 422 Unprocessable Entity を返す |

## 非機能要件
| # | 要件 |
|---|------|
| NF-01 | `http://localhost:8000/docs` で Swagger UI による API ドキュメントを確認できる |
| NF-02 | データベースは SQLite（ファイル1つで動くデータベース）を使い、サーバーを再起動してもデータが残る |

# ②学習目標
この書籍を終えると、次のことができるようになります。

- FastAPI のルーティング（GET / POST / PUT / DELETE）を実装できる
- Pydantic のモデルで、リクエストとレスポンスの形と入力チェックを宣言できる
- 404・422 などのステータスコードで、API の利用者に結果を正しく伝えられる
- SQLAlchemy の ORM を使って、データベースへの CRUD を実装できる
- `Depends` を使って、データベースとの接続（セッション）を安全に受け渡せる

# ③進め方
4つのフェーズに分けて、段階的にタスク管理 API を完成させます。

| 章 | フェーズ | 内容 | 習得する概念 |
|----|----------|------|------------|
| 入門03 | Phase 1 | 最小の FastAPI と Swagger UI | ルーティング / uvicorn / 自動ドキュメント |
| 入門04 | Phase 2 | インメモリで CRUD を作る | Pydantic モデル / POST / パスパラメータ / 404 |
| 入門05 | Phase 3 | バリデーションと部分更新 | `Field` / 422 / PUT・DELETE / クエリパラメータ |
| 入門06 | Phase 4 | SQLite と SQLAlchemy へ切り替える | ORM / セッション管理 / `Depends`（依存性注入） |

この書籍では、**まず Python のリストにデータを置いて（インメモリ）API を完成させてから、最後にデータベースへ差し替えます。** API の形（URL・入力・出力）を作る部分と、データを保存する部分を分けて作っておくと、保存先を変えるときの修正が小さく済むことを体験するためです。

コードを書き始める前に、次の入門02で設計（エンドポイント・データの形・処理の流れ）を確認します。

## Python を用意する
Python 3.10 以上が必要です。Windows の場合は、PowerShell で次のコマンドを実行するとインストールできます。

```powershell:PowerShell
winget install Python.Python.3.12
```

インストールしたらターミナルを開き直し、バージョンが表示されることを確認します。


## 作業フォルダと仮想環境を作る
任意の場所に作業フォルダ（例: `fastapi-task`）を作り、VS Code で開きます。VS Code のターミナル（PowerShell）で、仮想環境（venv）を作って有効にします。仮想環境は、このフォルダ専用のライブラリ置き場です。

```powershell:PowerShell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

行の先頭に `(venv)` と表示されれば有効になっています。以降のコマンドは、すべて仮想環境を有効にした状態で実行します。

:::message
「このシステムではスクリプトの実行が無効になっているため」というエラーになる場合は、初回だけ次のコマンドを実行してから、もう一度有効にしてください。

```powershell:PowerShell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```
:::

この書籍では、このフォルダに次のファイルを作っていきます。

```
fastapi-task/
├── venv/              # 仮想環境（上で作ったもの）
├── requirements.txt   # 使うライブラリの一覧（入門03で作る）
├── main.py            # API のプログラム（1ファイルにまとめる）
└── tasks.db           # SQLite のデータベースファイル（入門06で自動で作られる）
```
