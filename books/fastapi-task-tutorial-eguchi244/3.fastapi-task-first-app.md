# 最小のFastAPIとSwagger UI
第3章では、エンドポイントが1本だけの最小の FastAPI を動かし、Swagger UI から呼び出してみます（Phase 1）。

# 今回の目標物
- サーバーを起動し、`GET /tasks` で空の配列 `[]` が返る
- `http://localhost:8000/docs` で Swagger UI が開き、そこから API を呼び出せる

完成すると、Swagger UI は次の画面になります。見出しに「タスク管理API 1.0.0」が出て、その下に今回書く `GET /tasks` が1本だけ並びます。

![](/images/fastapi-task-tutorial-eguchi244/3.fastapi-task-first-app/2026-10-15-21-40-55.png =650x)

# ①ライブラリをインストールする
作業フォルダに `requirements.txt` を作成し、使うライブラリを書きます。

```text:requirements.txt
fastapi
uvicorn
sqlalchemy
```

| ライブラリ | 役割 |
|------|------|
| `fastapi` | API を作るためのフレームワーク。入力チェックに使う Pydantic も一緒に入る |
| `uvicorn` | 作った API を動かすサーバー |
| `sqlalchemy` | データベースを Python から操作するライブラリ（入門06で使う） |

仮想環境を有効にした状態で、まとめてインストールします。

```powershell:PowerShell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

SQLAlchemy は入門06まで使いませんが、先に入れておきます。SQLite 自体は Python に標準で入っているので、インストールは不要です。

# ②最小のアプリを書く
`main.py` を作成し、次の内容を書きます。

```python:main.py
"""
タスク管理API（FastAPI + SQLAlchemy + SQLite）
"""
from fastapi import FastAPI

app = FastAPI(title="タスク管理API", version="1.0.0")

@app.get("/tasks")
def read_tasks():
    """
    タスク一覧を取得

    Returns:
    - list: タスクオブジェクトのリスト
    """
    return []
```

上から順に、次のことをしています。

1. `FastAPI` を読み込み、アプリ本体 `app` を作る。`title` と `version` は Swagger UI の見出しに表示される
2. `@app.get("/tasks")` で、「`/tasks` に GET リクエストが来たら、すぐ下の `read_tasks` を呼んでね」と登録する
3. `read_tasks` は空のリスト `[]` を返す（データはまだ無い）

`"""` で囲んだ部分は **docstring**（関数の説明文）です。プログラムの動きには影響しませんが、FastAPI は docstring を Swagger UI に説明として表示します。

# ③サーバーを起動する
ターミナルで次のコマンドを実行します。

```powershell:PowerShell
uvicorn main:app --reload
```

`Uvicorn running on http://127.0.0.1:8000` と表示されれば起動しています。

- `main:app` は「`main.py` の中の `app` という変数」を起動する、という意味です
- `--reload` を付けると、`main.py` を保存するたびにサーバーが自動で再起動します。コードを書き換えたら、保存するだけで反映されます
- 止めるときは、ターミナルで `Ctrl + C` を押します

ブラウザで `http://localhost:8000/tasks` を開くと、`[]` と表示されます。

# ④このプログラムはどう動くのか
`read_tasks()` は、コードのどこからも呼ばれていないことに注目してください。この関数を呼ぶのは **FastAPI 自身**です。サーバーは起動後ずっと待機していて、HTTP リクエストが届いたときだけ、対応する関数を呼びます。

```
[ブラウザ / Swagger UI]
   │  HTTPリクエスト（GET /tasks）
   ▼
[uvicorn（サーバー）] ← 起動後はリクエストが来るのをずっと待っている
   │
   ▼
[FastAPI] URLとHTTPメソッドに一致する関数を探す（ルーティング）
   │        「GET /tasks」→ @app.get("/tasks") が付いた read_tasks
   ▼
read_tasks() が呼ばれる → 戻り値（Pythonのリストや辞書）を JSON に変換
   │
   ▼
[ブラウザ] ← HTTPレスポンス（JSON）が返る
```

`@app.get("/tasks")` のように関数の上に `@` で書くものを**デコレータ**と呼びます。ここでは「この URL へのこのメソッドのリクエストが来たら、この関数を呼ぶ」という対応表への登録です。

以降の章でエンドポイントを増やすことは、「URL と関数の対応表に行を増やすこと」だと考えてください。

:::message
JavaScript でボタンに `addEventListener` で「クリックされたら呼ぶ関数」を登録するのと同じ、**待機型**の構造です。きっかけがユーザーのクリックから HTTP リクエストに変わっただけです。
:::

# ⑤Swagger UI で呼び出してみる
## Swagger UI とは
FastAPI が、書いたコードから**自動で作る** API の説明書兼お試し画面です。エンドポイントを追加するだけで一覧に載り、ブラウザから実際にリクエストを送れます。curl や Postman などの道具を別に用意する必要はありません。

ブラウザで `http://localhost:8000/docs` を開くと、冒頭の「今回の目標物」の画面が表示されます。

## API を呼び出す
**この手順は、以降の章の動作確認でも毎回使います。**

1. `GET /tasks` の行をクリックして開く
2. 右上の「Try it out」を押す
3. 下に出てくる「Execute」を押す

実際にリクエストが送られ、結果が下に表示されます。「Server response」の Code が 200、Response body が `[]` になっていれば成功です。上には docstring がそのまま説明として表示されています。

![](/images/fastapi-task-tutorial-eguchi244/3.fastapi-task-first-app/2026-10-15-21-40-56.png =650x)

# ⑥動作確認
次の動作ができれば、この章は完了です。

- [✔] `http://localhost:8000/tasks` を開くと `[]` が返る
- [✔] `http://localhost:8000/docs` で Swagger UI が表示され、「タスク管理API 1.0.0」の見出しと `GET /tasks` が載っている
- [✔] Swagger UI で `GET /tasks` →「Try it out」→「Execute」で、Code 200・`[]` が返る

# まとめ
ここまでの内容で、最小の FastAPI が動きました。

- `uvicorn main:app --reload` でサーバーを起動する
- `@app.get("/tasks")` のデコレータで、URL と関数を対応づける（ルーティング）
- 関数の戻り値は、FastAPI が JSON に変換して返す
- Swagger UI（`/docs`）から API を呼び出して動作を確かめる

など、この書籍の土台になることを学ばれたと思います。
