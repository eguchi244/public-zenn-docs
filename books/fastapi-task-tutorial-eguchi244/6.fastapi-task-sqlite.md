# SQLiteとSQLAlchemyへ切り替える
第6章では、データの置き場所をリストから SQLite のデータベースに差し替えます（Phase 4）。これでタスク管理 API の完成です。

**エンドポイントの数も URL も、返すデータの形も一切変わりません。** 変わるのは「データをどこから取り出し、どこへ書き込むか」だけです。

# 今回の目標物
- 起動すると、作業フォルダにデータベースファイル `tasks.db` が自動で作られる
- サーバーを再起動しても、作成したタスクが残っている
- 入門05までの動き（部分更新・削除・絞り込み・404・422）がそのまま動く

完成すると、次のようにサーバーを再起動した後も `GET /tasks` で作成したタスクが返ってきます。

![](/images/fastapi-task-tutorial-eguchi244/6.fastapi-task-sqlite/2026-10-15-21-40-55.png =650x)

# ①入門05の問題を確認する
入門05までの API でタスクをいくつか作成してから、サーバーを止めて（`Ctrl + C`）起動し直し、`GET /tasks` を実行してみてください。`[]` が返り、タスクがすべて消えています。

**原因:** `tasks` リストはサーバーのメモリ上にあるだけで、サーバーを止めると消えます。起動し直すと `main.py` が最初から実行され、`tasks = []` から始まります。

**解決策:** データをファイルに書き込んで保存する**データベース**を使います。この書籍では、ファイル1つで動き、Python に標準で入っている **SQLite** を使います。

Python からデータベースを操作するには、本来は SQL という専用の言語で命令を書きます。この書籍では **SQLAlchemy** というライブラリを使い、SQL を書かずに Python のクラスとメソッドでデータベースを操作します（このやり方を **ORM** と呼びます）。

:::message
SQLite と SQLAlchemy の基本は、下記の記事も参考になります。

- [Python初心者向けSQLite入門](https://brian0111.com/python-sqlite-howto/)
- [SQLAlchemyでテーブル設計とORMの操作](https://zenn.dev/shimakaze_soft/articles/6e5e47851459f5)
:::

この章で書き換える箇所は次の4つです。

| 箇所 | 変更 |
|------|------|
| データベースの設定とテーブルの定義 | 追加（②） |
| `Task`（Pydantic） | 1行追加。インメモリの `tasks`・`next_id` は削除（③） |
| `get_db`・`get_task` | `get_db` を追加し、`get_task` をデータベース版に置き換え（④） |
| 5本のエンドポイント | 中身をデータベースの操作に書き換え（⑤）。URL と `response_model` はそのまま |

# ②データベースの設定とテーブルの定義
## import を書き換える
`main.py` の冒頭の import を、次のように書き換えます。

```python:main.py
"""
タスク管理API（FastAPI + SQLAlchemy + SQLite）
"""
from datetime import datetime, timezone

from fastapi import Depends, FastAPI, HTTPException
from pydantic import BaseModel, ConfigDict, Field
from sqlalchemy import Boolean, Column, DateTime, Integer, String, create_engine
from sqlalchemy.orm import Session, declarative_base, sessionmaker
```

`fastapi` から `Depends`、`pydantic` から `ConfigDict` が増え、`sqlalchemy` の2行が加わりました。

## データベースの設定
import の下（Pydantic モデルの**前**）に、データベースの設定を追記します。

```python:main.py
# ==========================================
# DB設定（SQLite）
#
# NOTE: SQLiteは既定で「作成したスレッドからのみ利用可」だが無効にすること!!
# FastAPIはリクエストごとに別スレッドで処理するため、"check_same_thread": False を指定する必要がある
# ==========================================

# データベースの保存先ファイル（SQLite）のパスを指定
DATABASE_URL = "sqlite:///./tasks.db"
# データベースへの接続管理を行うEngineを作成（SQLiteのマルチスレッド制限を無効化）
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
# データベース操作の窓口となるセッションクラスを作成
SessionLocal = sessionmaker(bind=engine)
# すべてのデータモデルクラスの土台（ベースクラス）を作成
Base = declarative_base()
```

| 行 | 役割 |
|------|------|
| `DATABASE_URL` | 接続先。「SQLite を使う（`sqlite:///`）」「今のフォルダ（`./`）の `tasks.db` というファイル」という意味 |
| `engine` | データベースとの接続を管理する窓口 |
| `SessionLocal` | データベースとの「やりとり（セッション）」を作る工場。呼び出すたびに新しいセッションができる |
| `Base` | テーブルを Python のクラスで定義するときの親クラス |

**`check_same_thread: False`:** SQLite は既定で「接続を作ったスレッドからしか使えない」ようになっています。FastAPI は複数のリクエストを並行してさばくために、処理を別々のスレッドで動かすことがあるので、この制限を外しておきます。

## テーブルの定義
設定の下に、`tasks` テーブルの定義を追記します。

```python:main.py
# Tasksのデータモデル定義とORM対応付け
class TaskModel(Base):
    # テーブル名を tasks に指定
    __tablename__ = "tasks"

    # id列：整数型、主キー設定、Index作成（検索高速化）で設定
    id = Column(Integer, primary_key=True, index=True)
    # title列：最大255文字までの文字列型、入力必須（NULL不可）で設定
    title = Column(String(255), nullable=False)
    # completed列：真偽型、初期値=False で設定
    completed = Column(Boolean, default=False)
    # created_at列：日時型、初期値=世界標準日時の現在時刻 で設定
    created_at = Column(DateTime, default=lambda: datetime.now(timezone.utc))

# 起動時にテーブルを自動生成
Base.metadata.create_all(bind=engine)
```

**ORM ― クラスとテーブルの対応づけ:** `TaskModel` は「`tasks` テーブルの1行」を Python のオブジェクトとして扱うための宣言です。`Column(...)` の1つ1つがテーブルの列になります。`Base.metadata.create_all` は、まだテーブルが無ければ作ってくれます（すでにあれば何もしません）。テーブルを作る SQL を自分で書く必要はありません。

**主キーの自動採番:** `primary_key=True` の `id` は、行を追加するときにデータベースが自動で番号を振ります。入門04・05で自分で管理していた `next_id` は要らなくなります。

**`default=lambda: ...` にする理由:** `default=datetime.now(timezone.utc)` と書くと、`datetime.now` が**起動時に1回だけ**実行され、その時刻がすべての行に使われてしまいます。`lambda:` で包んで「行を作るたびに呼ばれる関数」を渡すことで、行ごとに作成した時刻が入ります。

:::message
`Task`（Pydantic）と `TaskModel`（SQLAlchemy）は名前が似ていますが別物です。`Task` は **API の入出力の形**、`TaskModel` は**データベースの1行の形**です（入門02の「データ設計」）。
:::

# ③レスポンスモデルにORMからの変換を許す
`Task`（Pydantic）に1行追加します。

```python:main.py
class Task(BaseModel):
    """タスク情報のレスポンスモデル"""
    id: int
    title: str
    completed: bool
    created_at: datetime

    # DBから取得したデータをそのままPydanticのモデルでも変換を許可する
    model_config = ConfigDict(from_attributes=True)
```

あわせて、インメモリのデータ置き場（`tasks` リストと `next_id`）を**削除**します。

**`from_attributes=True`:** Pydantic のモデルは、ふつうは辞書から作ります。この設定を付けると、`task.title` のように**属性を持つオブジェクト**（= SQLAlchemy の `TaskModel`）からも作れるようになります。これにより、エンドポイントが `TaskModel` をそのまま `return` しても、`response_model=Task` が自動で `Task` の形に変換してくれます。

# ④セッションの管理 ― Dependsによる依存性注入
## get_db ― リクエストごとにセッションを開いて閉じる
データベースとのやりとりは「セッション」を通して行います。セッションは**リクエストごとに開いて、終わったら必ず閉じる**必要があります。閉じ忘れると、接続がたまり続けて動かなくなる原因になります。

これを確実にするのが、次の `get_db` と、FastAPI の `Depends` です。`Task` の下に追記します。

```python:main.py
# ==========================================
# 依存関数
# ==========================================

def get_db():
    """
    データベースセッションを生成・管理する依存関数

    リクエストごとに新しいセッションを作成して、API処理の終了後に
    成否を問わず必ずセッションをクローズ（切断）します。

    Returns:
        DB操作のためのセッションオブジェクト（API処理の終了後に閉じる）
    """
    # セッション（接続窓口）を新しく作成する
    db = SessionLocal()
    try:
        # 作成したセッションを呼び出し元に渡し、処理が終わるまで待機する
        yield db
    finally:
        # 正常終了・エラー発生に関わらず、必ずセッションを閉じる
        db.close()
```

エンドポイントの引数に `db: Session = Depends(get_db)` と書くと、FastAPI は次の順に動きます。

```
リクエストが届く
  → get_db() を実行：セッションを作り、yield で db を渡して一時停止
  → エンドポイントを db 付きで呼ぶ
  → エンドポイントが返す（または 404 などの例外が起きる）
  → get_db() の続きを実行：finally で db.close()
```

**`yield` と `finally`:** `return` の代わりに `yield` を使うと、関数は値を渡したところで一時停止し、あとで続きから再開できます。`try` / `finally` の `finally` は、途中で例外が起きても**必ず**実行されます。この2つの組み合わせで、「エンドポイントの前にセッションを開き、後で必ず閉じる」が実現します。

**依存性注入（DI）:** このように「必要なものを自分で作らず、引数で受け取る」形を**依存性注入**と呼びます。エンドポイント側はセッションの開け閉めを気にせず、データベースの操作だけに集中できます。テストのときに本物のデータベースを偽物に差し替えるのも簡単になります。

## get_task をデータベース版に置き換える
入門05の `get_task` を、次のように置き換えます。

```python:main.py
# ==========================================
# ヘルパー関数
# ==========================================

def get_task(task_id: int, db: Session) -> TaskModel:
    """
    指定されたIDのタスクを取得する

    Args:
        task_id : 検索対象のタスクID
        db      : DB操作のためのセッションオブジェクト

    Returns:
        見つかったタスクオブジェクト

    Raises:
        HTTPException : タスクが見つからない場合（404 Task Not Found）。
    """
    task = db.get(TaskModel, task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="Task not found")
    return task
```

リストを順に見ていた `for` 文が、`db.get(TaskModel, task_id)`（主キーで1行を探す）の1行になりました。見つからなければ `None` が返るので、そのときは入門05と同じく 404 を送り出します。

`get_task` には `Depends` を使いません。エンドポイントから直接呼び、エンドポイントが受け取ったセッションを引数で渡します。

# ⑤エンドポイントをデータベースの操作に書き換える
5本のエンドポイントを、次のように書き換えます。**URL と `response_model` は一切変わっていない**ことに注目してください。変わったのは、引数に `db: Session = Depends(get_db)` が増えたことと、関数の中身だけです。

```python:main.py
# ==========================================
# エンドポイント
# ==========================================

app = FastAPI(title="タスク管理API", version="1.0.0")

@app.get("/tasks", response_model=list[Task])
def read_tasks(completed: bool | None = None, db: Session = Depends(get_db)):
    """
    タスク一覧（?completed=true/false で絞り込み可）

    Args:
    - completed: 完了状態での絞り込み（省略時は全件）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - タスク一覧（ID順のJSON配列）
    """
    query = db.query(TaskModel)

    # 絞り込みがある場合（?completed=true/false）はcompletedが一致するものだけ格納する
    # NOTE: 絞り込みがない場合（?completed=None, 省略）はこの処理をスキップして全リストを返す
    if completed is not None:
        query = query.filter(TaskModel.completed == completed)

    # タスク一覧をID順に並び変えて返す
    return query.order_by(TaskModel.id).all()

@app.get("/tasks/{task_id}", response_model=Task)
def read_task(task_id: int, db: Session = Depends(get_db)):
    """
    タスク１件を取得

    Args:
    - task_id: 取得対象のタスクID
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - タスク1件（JSON）

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    return get_task(task_id, db)

@app.post("/tasks", response_model=Task, status_code=201)
def create_task(payload: TaskCreate, db: Session = Depends(get_db)):
    """
    タスクを新規作成

    Args:
    - payload: 検証済みの入力（不正な入力は422）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 登録したタスク（201）
    """
    task = TaskModel(title=payload.title, completed=payload.completed)
    db.add(task)
    db.commit()
    db.refresh(task)
    return task

@app.put("/tasks/{task_id}", response_model=Task)
def update_task(task_id: int, payload: TaskUpdate, db: Session = Depends(get_db)):
    """
    タスクを更新（渡された項目のみ反映する部分更新）

    Args:
    - task_id: 更新対象のタスクID
    - payload: 検証済みの入力（None の項目は変更しない。不正な入力は422）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 更新したタスク

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    task = get_task(task_id, db)

    if payload.title is not None:
        task.title = payload.title
    if payload.completed is not None:
        task.completed = payload.completed

    db.commit()
    db.refresh(task)
    return task

@app.delete("/tasks/{task_id}")
def delete_task(task_id: int, db: Session = Depends(get_db)):
    """
    タスクを削除

    Args:
    - task_id: 削除対象のタスクID
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 削除できたことを示す {"ok": true}

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    task = get_task(task_id, db)
    db.delete(task)
    db.commit()
    return {"ok": True}
```

インメモリ版とデータベース版で、何が置き換わったかを並べます。

| 処理 | インメモリ（入門05） | データベース（入門06） |
|------|------|------|
| 一覧 | `tasks` をそのまま / リスト内包表記で絞り込み | `db.query(TaskModel)` に `.filter(...)` を足し、`.order_by(TaskModel.id).all()` |
| 1件取得 | `for` 文で探す | `db.get(TaskModel, task_id)` |
| 作成 | `next_id` を振って `tasks.append` | `db.add` → `db.commit` → `db.refresh` |
| 更新 | 属性を書き換える | 属性を書き換えて `db.commit` |
| 削除 | `tasks.remove` | `db.delete` → `db.commit` |

## 書き込みは commit するまで確定しない
`db.add(task)` は「この行を追加する予定」をセッションに登録するだけで、まだデータベースには書き込まれていません。`db.commit()` を呼んだときに、初めて `tasks.db` に書き込まれます。

更新も同じです。`task.completed = ...` のように属性を書き換えたあと、`db.commit()` を呼ぶと、SQLAlchemy が変わった項目を見つけて、データベースを書き換える命令（SQL の UPDATE 文）を自動で送ります。

## db.refresh ― データベースが決めた値を読み戻す
`id`（自動採番）と `created_at`（`default` の関数）は、`commit` したときにデータベース側で決まる値です。`db.refresh(task)` で、その値を `task` オブジェクトに読み戻してから返します。これでレスポンスに正しい `id` と `created_at` が載ります。

## 一覧は ID の昇順で返す
データベースは、並び順を指定しないと行を返す順番を保証しません。`order_by(TaskModel.id)` で ID の昇順を明示しています。

```python:main.py
"""
タスク管理API（FastAPI + SQLAlchemy + SQLite）
"""
from datetime import datetime, timezone

from fastapi import Depends, FastAPI, HTTPException
from pydantic import BaseModel, ConfigDict, Field
from sqlalchemy import Boolean, Column, DateTime, Integer, String, create_engine
from sqlalchemy.orm import Session, declarative_base, sessionmaker

# ==========================================
# DB設定（SQLite）
#
# NOTE: SQLiteは既定で「作成したスレッドからのみ利用可」だが無効にすること!!
# FastAPIはリクエストごとに別スレッドで処理するため、"check_same_thread": False を指定する必要がある
# ==========================================

DATABASE_URL = "sqlite:///./tasks.db"
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine)
Base = declarative_base()

class TaskModel(Base):
    __tablename__ = "tasks"

    id = Column(Integer, primary_key=True, index=True)
    title = Column(String(255), nullable=False)
    completed = Column(Boolean, default=False)
    created_at = Column(DateTime, default=lambda: datetime.now(timezone.utc))

# 起動時にテーブルを自動生成
Base.metadata.create_all(bind=engine)

# Pydanticモデル
# ==========================================

    """タスク作成時のリクエストモデル"""
    title: str = Field(..., min_length=1, max_length=255)
    completed: bool = False

class TaskUpdate(BaseModel):
    """タスク更新時のリクエストモデル"""
    title: str | None = Field(None, min_length=1, max_length=255)
    completed: bool | None = None

    id: int
    title: str
    completed: bool
    created_at: datetime

# ==========================================

    データベースセッションを生成・管理する依存関数

    リクエストごとに新しいセッションを作成して、API処理の終了後に
    成否を問わず必ずセッションをクローズ（切断）します。

    Returns:
        DB操作のためのセッションオブジェクト（API処理の終了後に閉じる）
    """

    db = SessionLocal()
    try:
        # 作成したセッションを呼び出し元に渡し、処理が終わるまで待機する
        yield db
    finally:
        # 正常終了・エラー発生に関わらず、必ずセッションを閉じる
        db.close()

# ==========================================
# ヘルパー関数
# ==========================================

def get_task(task_id: int, db: Session) -> TaskModel:
    """
    指定されたIDのタスクを取得する

    Args:
        task_id : 検索対象のタスクID
        db      : DB操作のためのセッションオブジェクト

    Returns:
        見つかったタスクオブジェクト

    Raises:
        HTTPException : タスクが見つからない場合（404 Task Not Found）。
    """
    task = db.get(TaskModel, task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="Task not found")
    return task

# ==========================================

app = FastAPI(title="タスク管理API", version="1.0.0")

@app.get("/tasks", response_model=list[Task])
def read_tasks(completed: bool | None = None, db: Session = Depends(get_db)):

    タスク一覧（?completed=true/false で絞り込み可）

    Args:
    - completed: 完了状態での絞り込み（省略時は全件）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - タスク一覧（ID順のJSON配列）
    """

def read_task(task_id: int, db: Session = Depends(get_db)):
    """
    タスク１件を取得

    Args:
    - task_id: 取得対象のタスクID
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - タスク1件（JSON）

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    return get_task(task_id, db)

@app.post("/tasks", response_model=Task, status_code=201)
def create_task(payload: TaskCreate, db: Session = Depends(get_db)):
    """
    タスクを新規作成

    Args:
    - payload: 検証済みの入力（不正な入力は422）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 登録したタスク（201）
    """
    task = TaskModel(title=payload.title, completed=payload.completed)
    db.add(task)
    db.commit()
    db.refresh(task)
    return task

@app.put("/tasks/{task_id}", response_model=Task)
def update_task(task_id: int, payload: TaskUpdate, db: Session = Depends(get_db)):
    """
    タスクを更新（渡された項目のみ反映する部分更新）

    Args:
    - task_id: 更新対象のタスクID
    - payload: 検証済みの入力（None の項目は変更しない。不正な入力は422）
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 更新したタスク

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    task = get_task(task_id, db)

    if payload.title is not None:
        task.title = payload.title
    if payload.completed is not None:
        task.completed = payload.completed

    db.commit()
    db.refresh(task)
    return task

@app.delete("/tasks/{task_id}")
def delete_task(task_id: int, db: Session = Depends(get_db)):
    """
    タスクを削除

    Args:
    - task_id: 削除対象のタスクID
    - db: DB操作のためのセッションオブジェクト

    Returns:
    - 削除できたことを示す {"ok": true}

    Raises:
    - HTTPException: タスクが見つからない場合は404
    """
    task = get_task(task_id, db)
    db.delete(task)
    db.commit()
    return {"ok": True}
```

# ⑥動きを追いかけてみる
「買い物」と「掃除（完了）」の2件を作成してから、サーバーを再起動すると何が起きるかを追ってみます。

1. **起動** → `Base.metadata.create_all` が、`tasks.db` と `tasks` テーブルが無ければ作る
2. **`POST /tasks` に `{"title": "買い物"}`** → `get_db` がセッションを開いて `create_task` に渡す → `TaskModel` を作って `add` → `commit` で `tasks.db` に書き込まれ、データベースが `id=1` と `created_at` を決める → `refresh` で読み戻す → `response_model=Task` が `TaskModel` を `Task` の形に変換して 201 で返す → `get_db` がセッションを閉じる
3. **`POST /tasks` に `{"title": "掃除", "completed": true}`** → 同じ流れで `id=2` の行が書き込まれる
4. **サーバーを止めて起動し直す** → `main.py` が最初から実行されるが、`tasks.db` はファイルとして残っている。`create_all` はテーブルがあるので何もしない
5. **`GET /tasks`** → `db.query(TaskModel).order_by(TaskModel.id).all()` が `tasks.db` から2行を読み出して返す

インメモリだった入門05では 4 でタスクが消えていましたが、今はファイルに書き込まれているので残ります。

:::message
データを最初からやり直したいときは、サーバーを止めてから `tasks.db` を削除します。次に起動したときに、空のテーブルが作り直されます。
:::

次の動作ができれば、タスク管理 API の完成です。

- [✔] 起動すると作業フォルダに `tasks.db` ファイルが自動で作られる
- [✔] `POST /tasks` でタスクを2〜3件作成する
