# タスクの追加と一覧描画
第3章では、「入力したタスクが一覧に並ぶ」だけの最小構成を作ります（Phase 1）。CRUD の C（作成）と R（読み出し・表示）にあたる部分です。

# 今回の目標物
- 入力欄にタスク名を入れて追加ボタンを押すと、一覧に並ぶ
- Enter キーでも追加できる
- 空文字やスペースだけでは追加されない

完成すると次の画面になります。タスクを3件追加したところです。チェックボックス・削除ボタン（入門04）や件数の表示（入門05）はまだありません。

# ①まず全体の動きを理解する
ここから書くコードは、**上から順に実行されて終わり、ではありません**。JavaScript のプログラムは次の2段階で動きます。

1. **ページ読み込み時（1回だけ）:** ファイルが上から実行され、状態の用意と「フォームが送信されたらこの関数を呼んでね」という**予約（イベントリスナー登録）**をして、待機状態に入る
2. **待機後:** ユーザーが操作するたびに、予約しておいた関数が呼び出される

完成までの全体の流れは次のとおりです。この章で作るのは、いちばん上の「フォームを送信」の行です。

```
ページ読み込み時（1回だけ）
  DOM参照の取得 → 状態の初期化 → 関数の定義 → リスナー登録 → render()（初期描画）
  ここで「待機状態」に入る

以降はユーザーの操作がきっかけ:
  [フォームを送信]     → タスクを配列に追加        → render()   ← 入門03
  [一覧の中をクリック] → 該当タスクを削除/完了切替 → render()   ← 入門04
  [タブをクリック]     → filter を変更             → render()   ← 入門05
```

どの操作も「**状態（配列や変数）を変える → `render()` で画面を描き直す**」という同じ形をしています。章が進んで操作が増えても、この形は最後まで変わりません。

# ②HTML マークアップを作る
作業フォルダに `index.html` を作成し、次の内容を書きます。**これがこのアプリの完成形の HTML です。** 以降の章でも HTML は変わりません。

```html:index.html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>タスク管理アプリ</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <div class="app">
    <h1>タスク管理アプリ</h1>

    <!-- タスク追加フォーム -->
    <form id="taskForm" class="task-form">
      <input id="taskInput" type="text" placeholder="タスクを入力..." autocomplete="off">
      <button type="submit" class="btn btn-add">追加</button>
    </form>

    <!-- フィルタータブ -->
    <div class="filters">
      <button class="filter active" data-filter="all">すべて</button>
      <button class="filter" data-filter="active">未完了</button>
      <button class="filter" data-filter="completed">完了済み</button>
    </div>

    <!-- タスク一覧（イベントデリゲーションの親要素） -->
    <ul id="taskList" class="task-list"></ul>

    <!-- フッター（件数表示） -->
    <footer id="taskCount" class="task-count"></footer>
  </div>

  <script src="script.js"></script>
</body>
</html>
```

ポイントは3つです。

- タスク一覧の `<ul>` は**空**です。中身の `<li>` は JavaScript がデータから作ります。「HTML は器、中身は状態から描く」がこのアプリの基本方針です
- 入力欄と追加ボタンを `<form>` で包んでいます。追加ボタンのクリックでも Enter キーでも、同じ `submit` イベントが届くため、**処理を1本にまとめられます**
- フィルタータブの `data-filter="all"` のような **`data-*` 属性**は、入門05で「どのタブが押されたか」を JavaScript から読み取るために使います（この章ではまだ使いません）

:::message
`style.css` は入門01の「CSS について」でダウンロードしたものを、`index.html` と同じフォルダに置いてください。
:::

# ③状態とDOM参照を用意する
`script.js` を作成し、冒頭に DOM 参照と状態変数を書きます。

```js:script.js
/* ==========================================
 * タスク管理アプリ（Vanilla JS）
 * 状態管理・DOM描画・localStorage永続化
 * ========================================*/

// ==========================================
// DOM要素
// ==========================================
const taskForm      = document.getElementById('taskForm');
const taskInput     = document.getElementById('taskInput');
const filterButtons = document.querySelectorAll('.filter');
const taskList      = document.getElementById('taskList');
const taskCount     = document.getElementById('taskCount');

// ==========================================
// 状態変数
// NOTE: 単一の真実のソース（Single Source of Truth）
// ==========================================
let tasks  = [];    // タスク配列
let filter = 'all'; // 'all' | 'active' | 'completed'

// ==========================================
// localStorage Key
// ==========================================
const STORAGE_KEY = 'tasks';
```

**DOM 参照:** HTML の要素を JavaScript から操作するために、最初に一括で取得しておきます。`filterButtons`・`taskCount`・`filter`・`STORAGE_KEY` はこの章ではまだ使いませんが、入門05・06で使うので先に書いておきます。

**単一の真実のソース:** このアプリの表示は、`tasks` 配列と `filter` 文字列という**2つの状態変数だけ**から決まります（入門02の「状態設計」）。画面（DOM）を直接いじって状態を持たせるのではなく、「状態を変える → 状態から画面を描き直す」の一方通行に統一します。

**localStorage のキー:** `localStorage` は「キー（名前）」と「値」のペアでデータを保存する仕組みです。`'tasks'` はその名前で、入門06で使います。

# ④タスクを追加する関数を書く
タスクを1件作って `tasks` 配列に加える `addTask()` を追記します。

```js:script.js
// ==========================================
// タスク操作
// ==========================================

/**
 * 新しいタスクを作成してtasks配列に追加する
 *
 * @param {string} title - タスクのタイトル
 */
function addTask(title) {
  tasks.push({
    id: crypto.randomUUID(),
    title,
    completed: false,
    createdAt: new Date().toISOString(),
  });
}
```

この関数は**状態（`tasks`）を変えるだけ**で、画面には触りません。画面を描き直すのは次の `render()` の仕事です。

## crypto.randomUUID() ― 重複しない ID を振る
削除や完了切り替えの対象を特定するため、各タスクに重複しない ID が必要です。ブラウザ標準の `crypto.randomUUID()` は `"36b8f84d-df4e-4d49-..."` のような、実質的に重複しない文字列を作ります。

## title, という省略記法
プロパティ名と変数名が同じ場合、`title: title` は `title` と省略できます。

## new Date().toISOString() ― 作成日時
`"2026-09-04T05:53:00.000Z"` のような、世界共通でプログラムが扱いやすい形式（ISO 8601）の日時の文字列になります。

# ⑤描画関数とフォームのイベントをつなぐ
## 状態から画面を描く render()
最小限の `render()` を追記します。`tasks` 配列の中身を、1件ずつ `<li>` にして一覧に並べる関数です。

```js:script.js
// ==========================================
// DOM 描画
// ==========================================

/**
 * タスクリストのHTMLを作成する
 *
 * NOTE: タスクが存在しない時はタスクリストのHTMLを生成しない（描画なし）
 */
function render() {
  // タスクリストの描画をリセットする
  taskList.innerHTML = '';

  // タスクリストのHTMLを作成する
  tasks.forEach((task) => {
    // 要素を生成する(<li class="task-item">task.title</li>)
    const li = document.createElement('li');
    li.className = 'task-item';
    li.textContent = task.title; // XSS対策（textContent使用）
    // ul#taskList にタスクリストを追加
    taskList.appendChild(li);
  });
}
```

やっていることは「一覧を空にする → `tasks` の全件を `<li>` にして追加する」の2段階です。

**「全消し → 全描き直し」で単純に保つ:** `render()` は毎回 `taskList.innerHTML = ''` で一覧を空にしてから、全件を描き直します。「変わった行だけ書き換える」より無駄に見えますが、**状態と画面のずれが原理的に起きない**単純さが勝ります（この規模なら速度の問題もありません）。React のようなフレームワークは、このやり方を効率よく行う仕組みを持っています。

**`textContent` でタスク名を入れる:** タスク名はユーザーが自由に入力した文字です。`textContent` に入れると、`<b>` のようなタグを入力されても**ただの文字**として表示されます。理由は入門04で詳しく説明します。

## フォームの送信を受け取る
フォームが送信されたときの処理を追記します。まずは処理をその場に書きます。

```js:script.js
// ==========================================
// イベントリスナー
// ==========================================

// --- タスク入力欄 ---
taskForm.addEventListener('submit', (event) => {
  // Formの規定動作を止める（SPA用のページリロード対策）
  event.preventDefault();

  // バリデーション
  // NOTE: 前後の空白を除去した結果が空文字なら追加しない
  const title = taskInput.value.trim();
  if (title === '') return;

  // タスクリストを作成して描画する
  addTask(title);
  render();

  // タスク入力欄を空にしてフォーカスする
  taskInput.value = '';
  taskInput.focus();
});

// ==========================================
// 初期描画
// ==========================================
render();
```

フォームが送信されると、次の順に処理が進みます。

1. `event.preventDefault()` でページの再読み込みを止める
2. 入力値の前後の空白を `trim()` で取り除き、空文字なら `return` で何もせず終わる
3. `addTask(title)` で状態を変え、`render()` で画面を描き直す
4. 入力欄を空にして、カーソルを入力欄に戻す（続けて入力しやすくするため）

**`event.preventDefault()` ― フォームの既定動作を止める:** `<form>` の `submit` は、ブラウザの既定動作として「ページを再読み込みして送信」しようとします。この行を書き忘れるとページがリロードされ、追加したはずのタスクが消えます。試しにこの行をコメントアウトして、動きを確かめてみてください。

**`type="submit"` のボタン:** ②の HTML で追加ボタンを `type="submit"` にしているので、ボタンのクリックでも入力欄での Enter キーでも、同じ `submit` イベントが届きます。

**最後の `render()`:** 読み込み時に1回だけ実行される**初期描画**です。この時点では `tasks` が空なので何も表示されませんが、入門06で保存したタスクを読み込むようになると、ここで一覧が表示されます。

# ⑥イベントリスナーとイベントハンドラーに分ける
⑤では処理を `addEventListener` の中に直接書きました。動きはしますが、イベントが増えるとどこに何が書いてあるのか読みにくくなります。そこで、処理の部分を名前の付いた関数に切り出します。

```js:script.js
// ==========================================
// イベントハンドラー
// ==========================================

/**
 * タスク入力欄の送信イベントを処理する
 *
 * @param {SubmitEvent} event - フォーム送信のイベントオブジェクト
 */
function handleTaskSubmit(event) {
  // Formの規定動作を止める（SPA用のページリロード対策）
  event.preventDefault();

  // バリデーション
  // NOTE: 前後の空白を除去した結果が空文字なら追加しない
  const title = taskInput.value.trim();
  if (title === '') return;

  // タスクリストを作成して描画する
  addTask(title);
  render();

  // タスク入力欄を空にしてフォーカスする
  taskInput.value = '';
  taskInput.focus();
}
```

イベントリスナーの登録は、関数の名前を渡すだけの1行になります。

```js:script.js
// ==========================================
// イベントリスナー
// ==========================================

// --- タスク入力欄 ---
taskForm.addEventListener('submit', handleTaskSubmit);
```

| 用語 | 役割 | コードでの例 |
| :--- | :--- | :--- |
| **イベントリスナー** | イベントの発生を待つ仕組み。「〜が起きたら教えてね」という登録 | `taskForm.addEventListener('submit', ...)` |
| **イベントハンドラー** | イベントが起きたときに実行される関数。「起きたらこれを実行して」という中身 | `handleTaskSubmit` |

お店に例えると、イベントリスナーは入り口の「センサー」、イベントハンドラーはセンサーが人を検知したときに「いらっしゃいませ！」と動く「ロボット」です。登録の一覧（どのイベントで何を呼ぶか）と処理の中身が分かれるので、読みやすく、直すときも迷いにくくなります。

:::message alert
**よくあるミス:** `addEventListener('submit', handleTaskSubmit())` と括弧を付けて書くと、「送信時に呼ぶ関数を渡す」のではなく、**その場で実行**してしまいます。渡すのは関数そのもの（`handleTaskSubmit`）です。
:::

# ⑦動きを追いかけてみる
書き終えたら、「タスクを2件追加する」と何が起きるかを、コードで追ってみてください。

1. **ページを開く** → `script.js` が上から実行される。`tasks` は空の配列、`handleTaskSubmit` が submit に予約され、`render()` が空の一覧を描いて待機に入る
2. **「牛乳を買う」と入力して Enter** → `handleTaskSubmit` が呼ばれる → `addTask` で `tasks` が1件になる → `render()` が一覧を空にしてから1件を描く
3. **「企画書を提出する」と入力して追加ボタン** → 同じく `handleTaskSubmit` → `tasks` が2件になる → `render()` が一覧を空にしてから**2件とも**描き直す

3 で1件目も描き直していることに注目してください。「追加された1件だけを足す」のではなく、毎回「`tasks` の今の中身をそのまま画面にする」ので、画面が状態とずれることがありません。

# ⑧動作確認
次の動作ができれば、この章は完了です。

- [✔] 入力して追加ボタンを押すとタスクが一覧に追加される
- [✔] Enter キーでも追加される（ボタンと同じ動き）
- [✔] 空文字・スペースだけでは追加されない
- [✔] 追加後、入力欄が空になりカーソルが戻る
- [✔] リロードするとタスクが全部消える（まだ保存していないので正常です。入門06で解決します）
