# 完了切り替えと削除
第4章では、タスクの行にチェックボックスと削除ボタンを付けて、CRUD の U（更新）と D（削除）を実装します（Phase 2）。

# 今回の目標物
- チェックボックスをクリックすると完了になり、タスク名に打ち消し線が付く
- もう一度クリックすると未完了に戻る
- 削除ボタンで、そのタスクだけが消える

完成すると、各行の左にチェックボックス、右に削除ボタンが付きます。次の画面は2件目を完了にしたところで、打ち消し線が付いています。

![](/images/js-task-tutorial-eguchi244/4.js-task-toggle-delete/2026-10-14-20-33-45.png =650x)

この章で増える流れは次の1本です。クリックされたのがチェックボックスか削除ボタンかを見分けて、状態を変えてから描き直します。

```
[一覧の中をクリック] → handleTaskListClick()
  → 押された要素の data-id / data-action を読む
  → 'toggle' なら toggleTask(id)、'delete' なら deleteTask(id)   ← 状態を変える
  → render()                                                       ← 画面を描き直す
```

# ①更新・削除のロジックを書く
まずは「状態を変える」側の関数を2つ作ります。どちらも画面には触らず、`tasks` 配列だけを変えます。

## タスクを削除する ― deleteTask
`addTask` の下に追記します。

```js:script.js
/**
 * 指定ID以外のタスクでtasks配列を作り直す
 *
 * NOTE: 指定IDのタスクを削除すると同義です
 * @param {string} id - タスクのUUID
 */
function deleteTask(id) {
  tasks = tasks.filter((task) => task.id !== id);
}
```

**`filter` ― 「消す」ではなく「残す条件で作り直す」:** 配列の `filter` は、条件に合う要素だけを集めた**新しい配列**を返します。ここでは「ID が指定の ID **ではない**もの」を残すので、結果として指定のタスクだけが除かれます。それを `tasks` に入れ直しています。

:::details 参考: splice で配列から直接取り除く書き方
配列から要素を直接抜き取る `splice` を使っても書けます。このアプリでは使いません。

```js
function deleteTask(id) {
  // 削除したいタスクが「何番目（インデックス）」にあるかを探す
  const index = tasks.findIndex((task) => task.id === id);

  // 見つかった場合（-1以外）は、その位置から1要素だけ削除する
  if (index !== -1) {
    tasks.splice(index, 1);
  }
}
```

「何番目かを探す → 見つかったら1つ抜く」と手順が増えます。条件で絞る `filter` のほうが、意図が読み取りやすく、見つからなかった場合の考慮も要りません。
:::

## 完了状態を反転する ― toggleTask
`deleteTask` の下に追記します。

```js:script.js
/**
 * タスクの完了状態を反転して更新する
 *
 * @param {string} id - タスクのUUID
 */
function toggleTask(id) {
  // 指定IDのタスクを取得
  const task = tasks.find((t) => t.id === id);

  // タスクの完了状態を反転する
  // NOTE: undefined対策 - タスクを取得できない時は状態更新しない
  if (task) {
    task.completed = !task.completed;
  }
}
```

**`find` ― ID から1件を特定する:** `find` は条件に合う**最初の1件**を返します。見つからなければ `undefined` を返すので、`if (task)` で確かめてから書き換えます。

**`task.completed = !task.completed`:** `!` は真偽を逆にする演算子です。`false` なら `true` に、`true` なら `false` になります。

:::message alert
**よくあるミス:** `task.completed == !task.completed;` と `=` を2つ書くと、代入ではなく**比較**になります。エラーにはならず、何も変わらないまま処理が終わるため気づきにくい誤りです。
:::

# ②タスク1行分のDOMを組み立てる
## 型定義を書いておく
次に作る関数の引数「タスク」がどんな形かを、`script.js` の冒頭（DOM 参照の上）にコメントで書いておきます。

```js:script.js
// ==========================================
// 型定義
// ==========================================

/**
 * タスク1件（localStorage に保存する形）
 *
 * @typedef {Object} Task
 * @property {string} id - タスクのID（crypto.randomUUID() で作るUUID）
 * @property {string} title - タスクの内容
 * @property {boolean} completed - 完了していれば true
 * @property {string} createdAt - 作成日時（ISO 8601形式の文字列）
 */
```

あわせて、状態変数の `tasks` にも型を書き添えます。

```js:script.js
/**
 * 全タスクの一覧（画面の表示と保存の元になる）
 *
 * @type {Task[]}
 */
let tasks  = [];    // タスク配列
```

これは JSDoc というコメントの書き方で、プログラムの動きには影響しません。VS Code は JSDoc を読み取るので、`task.` と打ったときに `title` や `completed` が候補に出るようになり、打ち間違いに気づきやすくなります。

## createTaskElement ― 1行分の要素を作る
入門03の `render()` は、タスク名だけの `<li>` を作っていました。今回はチェックボックス・タスク名・削除ボタンの3つを持つ `<li>` が必要になるので、1行分を作る処理を専用の関数に切り出します。`render()` の**上**に追記してください。

```js:script.js
/**
 * タスクリストのli要素を作成する
 *
 * @param {Task} task - タスク
 * @returns {HTMLLIElement}　li要素のタスクリスト
 */
function createTaskElement(task) {
  // li要素を作成する
  const li = document.createElement('li');
  li.className = task.completed ? 'task-item completed' : 'task-item';

  // checkbox要素を作成する
  const checkbox = document.createElement('input');
  checkbox.type = 'checkbox';
  checkbox.checked = task.completed;
  checkbox.dataset.id = task.id;
  checkbox.dataset.action = 'toggle';

  // タイトルのspan要素を作成する
  const title = document.createElement('span');
  title.className = 'task-title';
  title.textContent = task.title; // XSS対策(textContent使用)

  // 削除用のbtn要素を作成する
  const deleteBtn = document.createElement('button');
  deleteBtn.type = 'button';
  deleteBtn.className = 'btn btn-delete';
  deleteBtn.textContent = '削除';
  deleteBtn.dataset.id = task.id;
  deleteBtn.dataset.action = 'delete';

  // li要素に各要素をまとめて追加する
  li.append(checkbox, title, deleteBtn);
  return li;
}
```

この関数が作る HTML は、次の形です（完了済みのタスクの例）。

```html
<li class="task-item completed">
  <input type="checkbox" data-id="36b8f84d-..." data-action="toggle" checked>
  <span class="task-title">企画書を提出する</span>
  <button type="button" class="btn btn-delete" data-id="36b8f84d-..." data-action="delete">削除</button>
</li>
```

**三項演算子でクラスを出し分ける:** `task.completed ? 'task-item completed' : 'task-item'` は「完了なら左、未完了なら右」という意味です。完了したタスクには `completed` クラスが付き、CSS の打ち消し線が効きます。

**`dataset.id` / `dataset.action` ― 要素に「自分が誰で何をするか」を持たせる:** `checkbox.dataset.id = task.id` は、HTML の `data-id="..."` 属性を付けるのと同じです。チェックボックスと削除ボタンの両方に、タスクの ID と操作の種類（`toggle` / `delete`）を書き込んでおきます。これが次の③で「どれが押されたか」を見分ける目印になります。

## なぜ innerHTML に文字列を流し込まないのか
次のように書けば、1行で `<li>` の中身を作れそうに見えます。

```js
// 危険な書き方（使わない）
li.innerHTML = `<span>${task.title}</span>`;
```

しかしタスク名は**ユーザーの自由入力**です。タスク名に `<img src=x onerror=alert(1)>` のような文字を入力されると、それが **HTML として解釈され、中のプログラムが実行されます**。これを XSS（クロスサイトスクリプティング）と呼びます。

`textContent` に入れた文字は、必ず「ただの文字」として扱われるため安全です。**ユーザーが入力したものを画面に出すときは `textContent`**。素の JavaScript で開発するうえで、最も大切なセキュリティの習慣です。

実際にタスク名に `<b>太字</b>` と入力すると、次のように太字にはならず、入力したとおりの文字が表示されます。

![](/images/js-task-tutorial-eguchi244/4.js-task-toggle-delete/2026-10-14-20-33-46.png =650x)

:::message
入門03から使っている `taskList.innerHTML = ''` は、一覧を**空にするだけ**でユーザーの入力を含まないので安全です。
:::

## render() を書き換える
`render()` の中で `<li>` を作っていた部分を、`createTaskElement` を使うように書き換えます。

```js:script.js
/**
 * タスクリストのHTMLを作成する
 *
 * NOTE: タスクが存在しない時はタスクリストのHTMLを生成しない（描画なし）
 */
function render() {
  // タスクリストの描画をリセットする
  taskList.innerHTML = '';

  // タスクリストのHTMLを作成する
  tasks.forEach((task) => {
    // ul#taskList にタスクリストのli要素を追加
    taskList.appendChild(createTaskElement(task));
  });
}
```

# ③イベントデリゲーションでクリックを1本にまとめる
## 1件ずつリスナーを付けない理由
チェックボックスと削除ボタンは、タスクの件数だけあります。しかも `render()` のたびに作り直されます。1つずつ `addEventListener` を付けると、描き直すたびに付け直しが必要になります。

そこで、**親要素の `<ul id="taskList">` に1つだけ**リスナーを付けて、中のどの要素がクリックされたかを見分けます。これを**イベントデリゲーション（委譲）**と呼びます。

## handleTaskListClick ― どれが押されたかを見分ける
`handleTaskSubmit` の下に追記します。

```js:script.js
/**
 * タスクリスト内のクリックイベントを処理する（イベント移譲）
 *
 * NOTE: タスクリストの削除・完了切り替えを action に応じて実行する
 * @param {MouseEvent} event - クリックイベントのオブジェクト
 */
function handleTaskListClick(event) {
  // クリックされた要素の data-id と data-action を取得
  const { id, action } = event.target.dataset;

  // idが存在しない場合は何もしない
  if (!id) return;

  // actionに応じた状態更新を実行する
  if (action === 'delete') {
    deleteTask(id);
  } else if (action === 'toggle') {
    toggleTask(id);
  } else {
    return;
  }

  // 画面を再描画する
  render();
}
```

イベントリスナーの登録も、フォームの下に追記します。

```js:script.js
// --- タスクリストの削除・完了切り替え（イベント移譲）---
taskList.addEventListener('click', handleTaskListClick);
```

処理は次の順に進みます。

1. `event.target` は**実際にクリックされた要素**です。その `dataset` から、②で仕込んだ `data-id` と `data-action` を取り出す
2. `<li>` の余白やタスク名など、`data-id` を持たない場所がクリックされたら、`return` で何もしない
3. `action` が `'delete'` なら `deleteTask`、`'toggle'` なら `toggleTask` で状態を変える
4. `render()` で描き直す

**`const { id, action } = event.target.dataset;`:** オブジェクトから同じ名前のプロパティを取り出して変数にする書き方（分割代入）です。`const id = event.target.dataset.id;` と `const action = event.target.dataset.action;` の2行をまとめて書いています。

## なぜ親要素でクリックを受け取れるのか
クリックイベントは、クリックされた要素から親要素へ順に伝わっていきます（**バブリング**）。チェックボックスをクリックすると、`<input>` → `<li>` → `<ul>` の順にクリックが伝わるので、`<ul>` で待っていれば中のどの要素のクリックも受け取れます。

```
[チェックボックスをクリック]
  <input data-action="toggle">  ← event.target（実際にクリックされた要素）
     ↑ 伝わる
  <li class="task-item">
     ↑ 伝わる
  <ul id="taskList">            ← ここに付けたリスナーが受け取る
```

利点は2つです。

- リスナーが1つで済む
- `render()` で `<li>` を作り直しても、親の `<ul>` は消えないので**リスナーの付け直しが要らない**

「全消し → 全描き直し」の `render()` と相性のよいやり方です。

:::details script.js の全体コード
```js:script.js
/* ==========================================
 * タスク管理アプリ（Vanilla JS）
 * 状態管理・DOM描画・localStorage永続化
 * ========================================*/

// ==========================================
// 型定義
// ==========================================

/**
 * タスク1件（localStorage に保存する形）
 *
 * @typedef {Object} Task
 * @property {string} id - タスクのID（crypto.randomUUID() で作るUUID）
 * @property {string} title - タスクの内容
 * @property {boolean} completed - 完了していれば true
 * @property {string} createdAt - 作成日時（ISO 8601形式の文字列）
 */

// ==========================================
// DOM要素
// ==========================================
/** タスクの入力フォーム */
const taskForm      = document.getElementById('taskForm');
/** タスクの入力欄 */
const taskInput     = document.getElementById('taskInput');
/** 絞り込みのボタン（すべて・未完了・完了済み） */
const filterButtons = document.querySelectorAll('.filter');
/** タスクの一覧を表示する要素 */
const taskList      = document.getElementById('taskList');
/** 残り件数と総件数を表示する要素 */
const taskCount     = document.getElementById('taskCount');

// ==========================================
// 状態変数
// NOTE: 単一の真実のソース（Single Source of Truth）
// ==========================================
/**
 * 全タスクの一覧（画面の表示と保存の元になる）
 *
 * @type {Task[]}
 */
let tasks  = [];    // タスク配列
/** 選択中の絞り込み（'all' | 'active' | 'completed'） */
let filter = 'all'; // 'all' | 'active' | 'completed'

// ==========================================
// localStorage Key
// ==========================================
/** localStorage に保存するときのキー */
const STORAGE_KEY = 'tasks';

// ==========================================
// タスク操作
// ==========================================

/**
 * 新しいタスクを作成してtasks配列に追加する
 *
 * @param {string} title - タスクのタイトル
 */
function addTask(title) {
  tasks.push({
    id: crypto.randomUUID(),
    title,
    completed: false,
    createdAt: new Date().toISOString(),
  });
}

/**
 * 指定ID以外のタスクでtasks配列を作り直す
 *
 * NOTE: 指定IDのタスクを削除すると同義です
 * @param {string} id - タスクのUUID
 */
function deleteTask(id) {
  tasks = tasks.filter((task) => task.id !== id);
}

/**
 * タスクの完了状態を反転して更新する
 *
 * @param {string} id - タスクのUUID
 */
function toggleTask(id) {
  // 指定IDのタスクを取得
  const task = tasks.find((t) => t.id === id);

  // タスクの完了状態を反転する
  // NOTE: undefined対策 - タスクを取得できない時は状態更新しない
  if (task) {
    task.completed = !task.completed;
  }
}

// ==========================================
// DOM 描画
// ==========================================

/**
 * タスクリストのli要素を作成する
 *
 * @param {Task} task - タスク
 * @returns {HTMLLIElement}　li要素のタスクリスト
 */
function createTaskElement(task) {
  // li要素を作成する
  const li = document.createElement('li');
  li.className = task.completed ? 'task-item completed' : 'task-item';

  // checkbox要素を作成する
  const checkbox = document.createElement('input');
  checkbox.type = 'checkbox';
  checkbox.checked = task.completed;
  checkbox.dataset.id = task.id;
  checkbox.dataset.action = 'toggle';

  // タイトルのspan要素を作成する
  const title = document.createElement('span');
  title.className = 'task-title';
  title.textContent = task.title; // XSS対策(textContent使用)

  // 削除用のbtn要素を作成する
  const deleteBtn = document.createElement('button');
  deleteBtn.type = 'button';
  deleteBtn.className = 'btn btn-delete';
  deleteBtn.textContent = '削除';
  deleteBtn.dataset.id = task.id;
  deleteBtn.dataset.action = 'delete';

}

 * タスクリストのHTMLを作成する
 *
 * NOTE: タスクが存在しない時はタスクリストのHTMLを生成しない（描画なし）
 */
function render() {
  // タスクリストの描画をリセットする
  taskList.innerHTML = '';

  // タスクリストのHTMLを作成する
  tasks.forEach((task) => {
    // ul#taskList にタスクリストのli要素を追加
    taskList.appendChild(createTaskElement(task));
  });
}

// ==========================================
// イベントハンドラー
// ==========================================

/**
 * タスク入力欄の送信イベントを処理する
 *
 * @param {SubmitEvent} event - フォーム送信のイベントオブジェクト
 */
function handleTaskSubmit(event) {
  // Formの規定動作を止める（SPA用のページリロード対策）
  event.preventDefault();

  // バリデーション
  // NOTE: 前後の空白を除去した結果が空文字なら追加しない
  const title = taskInput.value.trim();

  // タスクリストを作成して描画する
  addTask(title);
  render();

  // タスク入力欄を空にしてフォーカスする
  taskInput.value = '';
  taskInput.focus();
}

/**
 * タスクリスト内のクリックイベントを処理する（イベント移譲）
 *
 * NOTE: タスクリストの削除・完了切り替えを action に応じて実行する
 * @param {MouseEvent} event - クリックイベントのオブジェクト

function handleTaskListClick(event) {

  } else {

  render();

// ==========================================

// ==========================================

taskList.addEventListener('click', handleTaskListClick);

// ==========================================
// 初期描画
// ==========================================
render();
```

# ④動きを追いかけてみる
タスクが3件ある状態で、「2件目を完了にして、1件目を削除する」と何が起きるかを追ってみます。

1. **2件目のチェックボックスをクリック** → クリックが `<ul>` まで伝わり、`handleTaskListClick` が呼ばれる → `event.target` はチェックボックスなので `action` は `'toggle'` → `toggleTask(id)` で2件目の `completed` が `true` になる → `render()` が一覧を描き直し、2件目の `<li>` に `completed` クラスが付いて打ち消し線が出る
2. **1件目の削除ボタンをクリック** → 同じく `handleTaskListClick` → `action` は `'delete'` → `deleteTask(id)` で `tasks` が2件になる → `render()` が2件を描き直す
3. **タスク名の文字をクリック** → `handleTaskListClick` は呼ばれるが、`<span>` には `data-id` が無いので `return` して何も起きない

どの操作も「状態を変える関数 → `render()`」の順で、画面を直接書き換えている箇所は1つもありません。

# ⑤動作確認
次の動作ができれば、この章は完了です。

- [✔] チェックボックスをクリックすると打ち消し線が付き、もう一度クリックすると戻る
- [✔] 削除ボタンで該当タスクだけが消える（他のタスクは残る）
- [✔] タスクを5件以上追加してから真ん中を削除しても、正しい行が消える
- [✔] タスク名に `<b>太字</b>` と入力しても、太字にならず**そのまま文字として**表示される（XSS 対策の確認）

# まとめ
ここまでの内容で、タスクの完了切り替えと削除ができるようになりました。

- `filter`・`find` を使った配列の削除と更新
