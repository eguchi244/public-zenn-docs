# 教材の画像を記事・本に反映する

> このスキルは同じ基準で構成された Zenn リポジトリ間で共通。教材リポジトリの場所はプロファイルの「教材リポジトリ」、原本と公開先の対応は「下書きと公開の流れ」にある。教材リポジトリが「無し」のリポジトリでは使わない。

教材の画像は教材リポジトリ側で撮る（教材リポジトリにそのためのスキルがある。private-study-dev なら `tutorial-screenshots`）。このスキルはそれを**記事・本へ持ってくる**側の手順。作業は下書き用リポジトリ（原本のある側）で行い、公開側へは `draft-to-publish` の同期で反映する。

## 1. 教材を最新にして、画像の差分を見る

`source-material` スキルの手順で feature ブランチを切り、submodule を最新化して、前回の版からの差分を見る。

```bash
git -C <submodule> diff --stat <前回の版>..HEAD -- <教材のフォルダ>
```

画像（`.png` など）の追加・変更と、**教材の本文のどこにその画像が差し込まれたか**（`git -C <submodule> diff <前回の版>..HEAD -- <教材のフォルダ>/document/*.md`）を確認する。本でも、教材と同じ場面に差し込むのが基本。

## 2. Zenn の命名規約で取り込む

```bash
python -I .claude/skills/material-images/scripts/import_images.py \
  <このリポジトリ> <submoduleのパス> <画像ディレクトリ名> <教材内の画像>[@幅]...
# Windows の Python に渡すパスは cygpath -w で変換する
```

- **画像ディレクトリ名は、このリポジトリの方針に従う**（プロファイルの「画像ディレクトリの方針」。本の章なら章ファイル名 `3.js-timer-stopwatch` など）。公開側の階層（`images/<本の slug>/<章>/`）への移し替えは同期スクリプトが行う
- ファイル名は `YYYY-MM-DD-HH-MM-SS.png`。教材の画像には撮影日時が無いので、**教材リポジトリにコミットされた日時**を使い、同じ日時の画像は渡した順に1秒ずつずらす
- **1つのディレクトリの画像は1回の実行でまとめて、本文に載せる順に渡す。** 分けて実行すると連番が 0 からやり直しになり名前が重なる（中身が違えばスクリプトが上書きせずに止まる）
- 複数の章で同じ画像を使うときは、章ごとに取り込む（章のディレクトリをまたいで参照しない）
- 出力に本文へ貼る Markdown（`![](/images/<ディレクトリ>/<日時>.png =650x)`）が出る。幅は既定 650。狭い画面の画像などは `<画像>@300` のように個別に指定する

## 3. 原本に差し込む

- 教材で差し込んだ場面と同じところに入れる。**画像の前に、何の画面か・どこを見ればよいかを1〜2文で書く**（公開中の記事と同じ書き方。教材の説明文を、記事・本での呼び方に直して使う。例: 「Phase 2」→「入門04」）
- 番号付きリストの途中や、コードブロック・`:::details` の中に入れない
- 本の章の冒頭（`# 今回の目標物`）には、その章を終えたときの画面を置く

差し込んだら、参照切れと使われていない画像が無いことを確かめる:

```bash
B=books/<原本のslug>
for r in $(grep -ohE '/images/[^ )]+\.(png|jpg|gif)' $B/*.md | sort -u); do [ -f ".$r" ] || echo "参照切れ: $r"; done
for f in images/<取り込んだディレクトリ>/*; do grep -q "$f" $B/*.md || echo "未使用: $f"; done
```

`npx zenn preview` で画像が表示されることを確かめ、`commit-flow` でコミットする。参照の更新（` M <submodule>`）も同じコミットに入れ、本文に `教材: <リポジトリ>@<短縮ハッシュ>` を書く。

## 4. 公開側へ反映する

`draft-to-publish` スキルの手順 4〜6（同期スクリプト → `git status` で差分が画像と本文の追加だけであることを確認 → プレビュー → マージ＝公開）。件名は `[<記事・本の名前>]を修正`。マージ前に「マージすると公開されます」と確認する（ユーザーが公開まで頼んでいれば、それを確認とみなしてよい）。

## 撮り直された画像を反映するとき

教材で同じファイル名のまま撮り直された場合、コミット日時が変わるので取り込むと**新しい名前**になる。古い画像を `images/<ディレクトリ>/` から消し、本文の参照を新しい名前に付け替える（`import_images.py` の出力をそのまま使う）。古い画像を残すと未使用の画像になる。
