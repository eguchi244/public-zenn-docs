# 下書きから公開までの手順

> このスキルは同じ基準で構成された Zenn リポジトリ間で共通。**どのリポジトリが下書き用で、どれが公開用か**は `.claude/zenn-profile.md` の「下書きと公開の流れ」にある。まずそこを読む。

書きかけの記事・本は公開用リポジトリに置かない。公開用リポジトリは `published: true` で運用しており、`main` に入った時点で公開ページに反映されるため。

## 1. 下書き用リポジトリで書く

- `npx zenn new:article --slug <slug>` / `npx zenn new:book --slug <slug>` で作る。slug は `CLAUDE.md` の「slug の付け方」に従う（**公開用リポジトリでもそのまま使う slug なので、ここで決める**）
- `published: false` のまま書く
- 区切りごとに `commit-flow` スキルでコミットする。`published: false` なので下書き用リポジトリの `main` に入れても公開されない

## 2. 公開先の構成を把握する

複製する前に、公開用リポジトリの既存の記事・本を**実際に数本読み**、次を確認する。プロファイルの「記事の構成」に要点があるが、要約で済ませず原文を見る。

- frontmatter（`emoji`・`type`・`topics`・`published` の書き方、コメントの有無）
- 見出しの型（冒頭・結びの節、小見出しの番号の振り方、見出しレベルの使い方）
- 本の場合は章タイトルの書式と章冒頭の書き出し
- Zenn 記法（`:::message`・`:::details` など）の使いどころ

```bash
ls articles books/*/                       # 公開用リポジトリで
grep -n '^#' articles/<似た記事>.md        # 見出し構成。コードブロック内の # コメントも拾うので中身も読む
```

下書きと違う点を書き出しておき、4 で揃える。

## 3. 公開用リポジトリへ複製する

公開用リポジトリで `git switch -c feature/<内容>` してから複製する。

```bash
SRC=<下書き用リポジトリのパス>
DST=<公開用リポジトリのパス>

# 記事
cp "$SRC/articles/<slug>.md" "$DST/articles/"
cp -r "$SRC/images/<slug>"   "$DST/images/"        # 画像がある場合

# 本
cp -r "$SRC/books/<slug>"    "$DST/books/"
cp -r "$SRC/images/<章ファイル名>" "$DST/images/"   # 章ごとに。移動先は 4 で直す
```

複製するのは `articles/`・`books/`・`images/` の対象分だけ。教材の submodule（プロファイルの「教材リポジトリ」）は持ち込まない。

複製前に、公開用リポジトリに同じ slug・同じ画像ディレクトリが無いことを `ls` で確かめる。あれば上書きせずユーザーに確認する。

## 4. 公開用に調整する

- **`published: true` に変える**（記事は frontmatter、本は `config.yaml`）
- **構成・書式を公開先に揃える。** 2 で把握した frontmatter・見出しの型・章タイトルの書式との差分を直す。見出しの組み替えや大きな書き直しになる場合は、直す前にユーザーに確認する
- **画像ディレクトリの方針を公開用リポジトリに合わせる。** 両リポジトリのプロファイルの「画像ディレクトリの方針」を見比べ、違えば画像を移動して参照パス `![](/images/...)` を書き換える
- **`config.yaml` の書き方を公開用リポジトリの zenn-cli に合わせる。** プロファイルの「config.yaml の現状」を見る
- 参照パスの漏れを確認する: `grep -rn '/images/' articles/<slug>.md books/<slug>/` の各ディレクトリが `images/` に実在すること

## 5. プレビューで確認する

```bash
npx zenn preview     # 公開用リポジトリで。エラーが無く、画像が表示されること
```

## 6. コミットしてマージする（＝公開）

`commit-flow` スキルに従う。件名は `[<記事・本の名前>]を投稿`。

**`main` へのマージがそのまま公開になる。** マージ前にユーザーへ「マージすると公開されます」と一言確認する。

## 7. 下書き用リポジトリの後始末

下書きを残すか消すかは**ユーザーに確認する**。以降の修正をどちらで行うかも同時に確認する（両方に残すと内容が食い違っていく）。

消す場合は記事・本と対応する `images/` を一緒に消し、`commit-flow` で `[<名前>]を削除` としてコミットする。
