# スクラップを素材にする手順

> このスキルは同じ基準で構成された Zenn リポジトリ間で共通。どのリポジトリが下書き用かはプロファイルの「下書きと公開の流れ」にある。取り込みは**下書き用リポジトリ**で行う。

## 考え方

- **スクラップは GitHub 連携の対象外。** zenn-cli でも扱えず、リポジトリに置いても Zenn には反映されない。素材として取り込んで記事・本の原本にする
- Zenn の API（`https://zenn.dev/api/scraps/<id>`）は本文を HTML（`body_html`）でしか返さない。`fetch_scrap.py` が Zenn の Markdown に戻す
- **画像は Zenn のサーバーにしか無いことが多い。** 取り込み時にリポジトリへダウンロードしておく（元スクラップを消すと画像も消えるおそれがある）

## 1. 取り込む

公開時の slug を `CLAUDE.md` の「slug の付け方」で先に決め、原本の slug（`<公開slug>-draft`）で取り込む。

```bash
python -I .claude/skills/scrap-import/scripts/fetch_scrap.py \
  <スクラップのURLかid> <下書き用リポジトリ> articles/<公開slug>-draft.md <公開slug>-draft
# Windows の Python に渡すパスは cygpath -w で変換する
```

- 本文を `articles/<公開slug>-draft.md` に、画像を `images/<公開slug>-draft/` に置く。出力先が既にあれば上書きせず中止する
- 画像のファイル名は規約の `YYYY-MM-DD-HH-MM-SS.<拡張子>`。撮影日時は分からないので、コメントの投稿時刻から1秒ずつずらして掲載順に付ける
- 標準出力に**画像の対応表**（番号・ファイル名・元URL・直前の見出しと本文）が出る。2 で使う
- 変換できない要素は警告が出る（テキストは残る）。警告が出たら該当箇所を元のスクラップと見比べて手で直す
- 本にする場合も一旦1ファイルに取り込み、見出し単位で章ファイル（`books/<slug>-draft/<番号>.<name>.md`）へ分ける。画像はプロファイルの「画像ディレクトリの方針」に合わせて移す

変換されるもの: 見出し・段落・改行・リスト・リンク・強調・表・コードブロック（`言語:ファイル名`）・`:::message`（`alert` も）・`:::details`・リンクカード（単独行の URL）。コメントが複数ある・返信があるときは、投稿順に `<!-- コメント: 日時 -->` の区切りを付けて並べる。

## 2. 画像を置き換える

取り込んだ画像を **Read で1枚ずつ開いて**中身を確かめ、出どころ（自分で撮ったものか、他サイトから持ってきたものか）をユーザーに確認したうえで、次の方針で置き換える。

| 写っているもの | 置き換え |
|---|---|
| ターミナル・コマンドプロンプトの入力と出力 | 画像に写っている内容を書き起こして**コードブロック**にする（読者がコピペできる）。入力と出力でブロックを分ける |
| 公式サイトなど Web ページの画面 | そのページの URL を単独行に置いて**リンクカード**にする |
| それ以外（インストーラー・アプリの操作画面、ロゴなど） | 画像のまま使う |

- 書き起こしは画像のとおりにする（バージョン番号なども変えない）。プロンプトに写っているユーザー名などの個人情報は書かない（`C:\>` などにする）
- **置き換えた画像はファイルも消す**（孤児画像を残さない。`sync_article.py` は孤児画像があると失敗する）
- 画像の幅は公開側の記事に合わせて `=500x` などを付ける（プロファイルの「記事の構成」と既存記事を見る）

## 3. 原本にする

- 先頭の元スクラップ情報のコメントは消してよい（元 URL はコミット本文に残す）
- frontmatter を公開側の型で付け、`published: false` にする
- 構成・書式を公開側に揃える。手順は `draft-to-publish` スキルの 2・3。スクラップは書き足しながら作られるので、見出しの番号やレベルがずれていることが多い。組み替えが大きくなる場合は、直す前にユーザーに確認する
- 以降は `draft-to-publish` の 3〜7（プレビュー → コミット → 同期 → マージ＝公開）。記事の同期は `sync_article.py`

## 4. 新しいスクラップにする場合

スクラップは zenn-cli で作れない。整理した Markdown を作ってユーザーに渡し、Zenn の画面に貼ってもらう。リポジトリには置かない（取り込んだ素材と画像も、使い終わったら消す）。画像はリポジトリのパスでは表示されないので、Zenn の画面でアップロードし直す必要があることを伝える。

## 5. 元スクラップの扱い

公開後に、元スクラップをどうするかユーザーに確認する。

- 削除する／記事へのリンクを最後に追記してクローズする／そのまま残す
- **操作は Zenn の画面でユーザーが行う**（API や GitHub 連携では操作できない）
- 削除やクローズは、**本番の記事ページで本文と画像が表示されることを確かめてから**にする

## コミット

`commit-flow` に従う。件名は `[<記事の名前>]を投稿`。本文に `元スクラップ: <URL>（<取り込み日>）` を書き、画像を置き換えた場合はその内訳（何枚をコードブロック・リンクカードにしたか）も書く。
